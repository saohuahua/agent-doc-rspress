# Pi 原理

这个板块回答一件事：**一个能跑通的最小 Agent，要变成真实产品还差什么。**

默认你已经知道 Agent 的基本结构是“模型决策 → 工具执行 → 结果回填 → 再次决策”，所以每一章都从同一条路径展开：

```
最小实现长什么样
      ↓
进入真实产品后暴露什么问题
      ↓
Pi 为此增加了哪些结构
      ↓
每个结构为什么放在那个位置
      ↓
这些结构仍然抹不平什么 / 自己开发时该怎么补
```

代码只在“不看这段就说不清”的时候出现，完整的 file:line 索引放在每页末尾的折叠区。

## 5. 引用规则

:::danger 每个行号都可机器校验

```bash
pnpm check:refs
```

脚本拿本机 Pi 源码逐条核对：路径存不存在、行号越没越界、**符号是否出现在声明行号 ±3 行内**。

已经用它抓到过真实错误：

- `learn/08` 把 `SessionTree` 写在 `session/session.ts`，实际接口在 `packages/agent/src/harness/session/types.ts:328`
- 交接文档给的 `agent-loop.ts` 行号指向**调用点**而非定义（`runLoop` 说 116，定义实际在 `packages/agent/src/agent-loop.ts:155`）

**不要抄任何二手行号，包括项目自己的交接文档。**

:::

另外两条：

- 引用 `AgentHarness` 的任何类型时，**必须同时标注其未实现状态**
- 允许"拆解了某设计并能说明取舍"，不允许"设计了某语义"

## 6. 怎么读

每章都默认你会写最小 Agent，不重复入门概念。如果 `messages`、tool call、流式、上下文窗口这些词读起来吃力，先回 [Learn Agent](/learn/) 过一遍。

| 你的目的 | 建议路径 |
|---|---|
| 准备面试，时间紧 | 先读各章总览页的“演进图 + 小结”：01 → 03 → 05 → 04 |
| 想搞懂一次请求的完整链路 | 02 → 03 → 04 → 06，并读详解页 |
| 准备做二次开发 | 01 → 09 → 04 |
| 想讲清“可靠性” | 03.2 → 04 → 07 → 10 |
| 要在 CI / 后台无人值守跑 Pi | [03.2 无人值守预算](./03-agent-loop/termination) 优先 |
