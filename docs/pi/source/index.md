# Pi 源码深入

这个板块**不按代码目录组织，按设计问题组织**。

原因很直接：按目录读会强迫你啃面试不会问的东西。比如启动链路要读 6549 行的 `interactive-mode.ts`，读完几乎不产生任何可讲的内容。

## 3. 每章固定产物

每章必须回答完这 6 件事，缺一不可：

| # | 产物 | 判据 |
|---|---|---|
| 1 | 本章回答哪个面试问题 | 写出编号 |
| 2 | 问题是什么 | **必须是一个具体场景**，不是抽象描述 |
| 3 | Pi 怎么做的 | 每个符号带 `file:line` |
| 4 | 为什么这样做 | 至少一个替代方案 + 取舍 |
| 5 | 边界 | 抹不平什么、什么情况下失效 |
| 6 | 未验证标记 | 哪些是推断，哪些实际跑过 |

## 4. 源码引用硬规则

:::danger 引用不许手写，必须过校验

```bash
pnpm check:refs
```

脚本会拿本机 Pi 源码逐条核对：路径是否存在、行号是否越界、**符号是否出现在声明行号 ±3 行内**。

已经用它抓到过两类真实错误：

1. `learn/08` 把 `SessionTree` 写在 `session/session.ts`，实际接口在 `session/types.ts:328`
2. 交接文档 §2/§8 给的 `agent-loop.ts` 行号指向的是**调用点不是定义**（`runLoop` 116→实际 155）

所以：**不要抄任何二手行号，包括交接文档自己的。**

:::

其余规则：

- 用仓库相对路径，不用本机绝对路径
- 引用 `AgentHarness` 的任何类型时，**必须同时标注其未实现状态**
- 允许的表述是「拆解了某设计并能说明取舍」，不允许「设计了某语义」
