# 回溯基础 搜索分支与状态恢复

相关基础：[TypeScript 运行时与递归](/leetcode/00-intro/03-ts-runtime-and-recursion) 了解函数调用栈，以及 [复杂度与数据结构](/leetcode/00-intro/02-complexity-and-structures) 了解指数输出。回溯的起点是手工尝试：先作一个选择，继续填写，如果失败或完成，就回到最近还能换选择的位置。

## 选择过程的树形表示

例如排列一和二，根节点没有选择，第一层可以选一或二。选一以后第二层只能选二，得到一二；返回根再选二，下一层选一，得到二一。树上的节点代表已经作出的选择，边代表新选择。递归负责按深度访问分支并返回父节点；完整性与去重性仍由候选规则和状态恢复保证。

每道题必须重新回答：这一层决定什么，候选有哪些，哪些已经不合法，怎样算完整答案。全排列每层填一个位置，子集每个前缀都可记录，单词搜索每层匹配一个字符，皇后每层决定一行。它们都用递归，但状态和终止语义不同。

## 路径 进度与约束

路径保存正在构造的答案，如数字数组或字母数组。进度说明下一步处理哪里，如下标、行号或剩余和。约束记录本分支不能再选什么，如已使用位置、已占用列。并不是每题都需要三类独立变量，子集用递增起点就能保证不重复位置，不必再维护used。

TypeScript中的数字参数传入下一次调用后，改下一层的局部变量不会改回当前层。数组与Set却通过引用共享，所以push、add会影响当前工作状态，返回后必须对应pop、delete。先区分哪些状态共享，再决定需要撤销什么。

## 状态撤销与分支隔离

完整过程是检查候选、记录选择、深入、撤销。撤销后，下一候选应面对与上一候选尝试前相同的路径与约束。如果只pop而忘记used=false，后面的分支就被错误封锁；如果只清标记却不pop，答案路径会夹杂前一分支的残留。

保存结果时复制数组，例如展开path产生新数组。只保存path引用会让后面的pop改变过去答案。字符串join生成独立值，后续改路径数组不会改变字符串。成功时提前返回也必须清理状态，单词搜索尤其容易因短路而跳过恢复。

## 剪枝的成立条件

括号前缀右括号比左括号多，未来加字符不能改变那个已经失败的前缀，所以可以剪。正数和超目标，继续添加正数只会更大，所以可以剪。短片段ab不是回文，但延长成aba可能回文，所以不能据此停止尝试更长终点，只能跳过当前片段。

剪枝需要证明当前前缀的所有后续扩展均不可能构成有效答案。条件改变会推翻证明，例如允许负数时总和超额仍可能被拉回，就不能沿用正数剪枝。

## 去重与合法性约束

排列用used避免同一位置在一条路径重复使用。组合通过下标不下降避免相同集合以不同顺序出现。输入含重复值时，还可能需要同层跳过相同数。同一位置复用、相同值重复和最终答案重复是三类不同约束，需要分别设计标记或生成顺序。

## 复杂度和适用边界

如果要求输出全部子集，输出本身就有指数数量；全部排列则有阶乘数量。复杂度应同时计算搜索和复制答案，单层循环的数量不能代表整棵搜索树的规模。辅助空间包括路径、约束和递归栈，输出存储单独说明。若只求存在性或最优值，可能能合并重复状态；若每条不同路径本身就是输出，不能随意用全局已访问标记丢掉它们。
