# 0022 括号生成

相关基础：[本章基础](/leetcode/10-backtracking/)。题目来源：[力扣 22](https://leetcode.cn/problems/generate-parentheses/)。

## 题目

:::info 题面

**难度**：中等

给正整数n，生成全部由n对括号组成的合法字符串。每个结果长度2n，左右括号分别n个，且每个前缀左括号数量不少于右括号。只满足最终数量相等还不够，)(虽然各一个，却不能形成合法嵌套。

:::

### 官方示例

> **示例 1**
>
> 输入：n = 3
> 输出：["((()))","(()())","(())()","()(())","()()()"]

> **示例 2**
>
> 输入：n = 1
> 输出：["()"]

### 约束

- 1 <= n <= 8

## 前期思路

### 朴素方法与复杂度

最直接是在2n个位置都尝试左右括号，生成全部二进制选择，再检查是否合法，上界4^n种字符串。很多字符串第一个字符就是右括号，或中途右括号太多，从那一刻就已经不可能被后续字符救回来，却还继续填满，浪费了整棵后续分支。

### 从失败前缀发现规则

合法括号扫描时，右括号必须匹配此前还没关闭的左括号。因此维护open和close两个已使用数量。只要close>open，就存在一个右括号没有前面的搭档；未来再放左括号不能跑到这个右括号前面，所以该前缀永久失败，可以不生成它。

另一个限制是左括号最多n个。只要open<n，就还可以放左括号；只要close<open，就可以放右括号。这两条条件把合法性判断提前到生成过程，让每条保留路径都具有成为完整答案的可能性。

### 算法推导

从空path、open=0、close=0开始。每层尝试符合条件的两种字符。放左括号时open加一，放右括号时close加一。两个计数作为函数参数传入，不会被子调用永久改变；path是共享数组，所以返回后需要pop撤销。

当open和close都等于n时，已经生成完整且合法的结果，将path.join('')保存。也可以用长度2n作为终止，但双计数形式直接对应题意。任何输出的每个前缀都满足close<=open且总量正确，因此合法。

反过来任一合法答案的每个位置，都不会违反这两条条件，所以它的选择路径一定会被尝试。每个不同字符串对应不同左右选择序列，不会重复。剪掉的是已经违反必要条件的前缀，而不是依据“看起来不太好”随意删分支。

### 变式分析与错误反例

- 若增加中括号类型，两个计数不足以判断嵌套类型，([)]数量平衡仍不合法，需要维护尚未关闭的括号栈并限制对应类型。若只求数量，可以用计数动态规划或组合关系，不必输出所有字符串。错误在open==close时保存答案，会过早保存空串或()，未使用完指定对数。

## 执行过程示例 两对括号

| 前缀 | 已用左与右 | 可以继续做什么 |
| --- | --- | --- |
| 空 | 0和0 | 只能放左 |
| ( | 1和0 | 可以再左 也可以右 |
| (( | 2和0 | 左已满 只能右 |
| (() | 2和1 | 只能右 得到(()) |
| () | 1和1 | 只能左 得到()( |
| ()( | 2和1 | 只能右 得到()() |

表中从完成第一条回到单个左括号的分支时，会撤销多次字符，再尝试右括号。最终两个结果，没有生成任何以右括号开头的无效字符串。

## 解法复述与检查

- 为什么右括号不能先出现？
- 为什么close==open时还可能没完成？

:::details 算法概述

逐字符构造字符串，保存已用左右括号数量。左括号还没用完可以添加，右括号只有在此前左括号更多时才能添加。这样所有前缀都合法，两个数量都达到n时保存答案。每次递归返回撤销当前字符，继续尝试另一种选择。

:::

## 复杂度与边界

- 设合法结果数为C，时间可保守写**O(n·4^n)**，实际受合法前缀剪枝远小于枚举所有字符串；输出空间**O(nC)**，辅助path和递归栈**O(n)**。
- 不修改输入。
- n=1只生成()。
- 合法数量是卡特兰数，但理解过程不依赖记住这个计数公式，也不把输出指数规模误称线性。

## 分层提示

:::details 提示一 观察方向

一个前缀右括号比左括号多 后面再加字符还能修好吗

:::

:::details 提示二 需要的信息

记录已用左右数量 右括号需要一个尚未关闭的左括号

:::

:::details 提示三 组织步骤

左未满可放左 右少于左可放右 两边都满才保存 返回撤销字符

:::

## TypeScript 实现

本地使用命名导出供测试调用 提交力扣时按题目入口移除导出声明

```ts
export function generateParenthesis(n: number): string[] {
  const result: string[] = []
  const path: string[] = []
  const visit = (open: number, close: number): void => {
    if (open === n && close === n) {
      result.push(path.join(''))
      return
    }
    if (open < n) {
      path.push('(')
      visit(open + 1, close)
      path.pop()
    }
    // 右括号只能关闭此前尚未匹配的左括号
    if (close < open) {
      path.push(')')
      visit(open, close + 1)
      path.pop()
    }
  }
  visit(0, 0)
  return result
}
```
