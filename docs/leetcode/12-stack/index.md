# 栈基础 后进先出与待处理状态

输入一对括号时，内层括号要先闭合；执行一次函数调用时，最近进入的调用要先返回。它们共同的规则是最近加入的任务最先完成。把这个规则固定下来就是栈。

相关基础：[数组操作与递归栈](/leetcode/00-intro/03-ts-runtime-and-recursion)。本章的栈是手工维护的数组，和引擎维护的函数调用栈概念相似，但不是同一个对象。

## 栈的操作与后进先出规则

栈顶是最近加入、下一次可取出的元素。入栈push把元素放到末尾，出栈pop移除末尾，查看末项不会删除。依次放入A、B、C后，弹出顺序是C、B、A。不能从底部取A却仍声称遵循后进先出。

算法使用栈不是因为数组方便，而是因为它需要这个处理次序。有效括号要先配对最近的未闭合左括号；字符串解码要先完成最近打开的内层片段。保存什么取决于之后恢复需要什么，可能是字符、下标，也可能是一组局部状态。

## 下标与查询所需信息

每日温度要返回等待天数，知道之前温度是70还不够，还要知道发生在第几天。保存下标就同时得到日期，以及通过输入数组读取的温度。单纯保存数值会丢失计算距离需要的信息。

柱状图同样需要左右边界位置。下标既能定位高度，也能表达矩形宽度。保存内容应由输出所需信息确定；需要位置差或边界宽度时，仅保存元素值不足以恢复答案。

## 单调栈与批量结算

一般栈没有大小顺序。某些题中，当前值能一次解决最近的一批待办任务，而解决不了的更早任务暂时留下。这时可以主动维护栈内值的单调关系。

温度73、71、72依次到来。73还没等到更高温度，71也在等待。72到来能解决71，但不能解决73，所以弹出71而保留73，再把72加入。栈里存的不是所有历史，而是尚未等到答案的位置。弹出的任务已经永久得到答案，不应再放回去等待第二次。

为什么有while循环仍是线性？每个位置入栈一次，最多出栈一次。某一步连续弹出很多项，意味着后面已经不会再次处理这些项。将所有步骤合起来计数，出入栈总数不超过常数倍n。

## 相等值的处理规则

每日温度要求严格更暖，相等不能结算等待。柱状图可以允许相等高度留在栈里，并让较早位置最终获得更宽的候选。也可以使用别的相等策略，但宽度解释必须与实现一致。严格比较与非严格比较会改变相等项的处理规则，必须与题意和边界证明一致。

## 额外状态和哨兵

最小栈需要查询当前所有元素的最小值。可以每层同时保存截至这里的最小值，弹出时自然回到前一层记录，不用重新扫描。哨兵则是人为增加的边界记录，例如下标负一代表左边没有更矮柱子。它不是输入里的真实元素，必须解释何时读取以及为什么不会错误访问。

分析栈算法时，需要明确每项保存的待处理信息、当前输入触发的结算条件，以及弹出后不再参与计算的依据。比较条件和状态含义共同决定算法是否适用。
