# 0739 每日温度

每个位置需要查找其后第一个温度更高的位置。按时间顺序读取新温度时，可以同时结算一批尚未找到答案的日期，避免从每个位置分别扫描后缀。

相关基础：[本章基础](/leetcode/12-stack/)。[力扣原题](https://leetcode.cn/problems/daily-temperatures/)。

## 题目

:::info 题面

**难度**：中等

输入每日温度数组，输出每个位置到之后第一天严格更高温度的距离。如果后面没有更高温度，对应输出零。要求最近的一天，相等温度不算，也不是统计之后更暖的天数。

:::

### 官方示例

> **示例 1**
>
> 输入: temperatures = [73,74,75,71,69,72,76,73]
> 输出: [1,1,4,2,1,1,0,0]

> **示例 2**
>
> 输入: temperatures = [30,40,50,60]
> 输出: [1,1,1,0]

> **示例 3**
>
> 输入: temperatures = [30,60,90]
> 输出: [1,1,0]

### 约束

- 1 <= temperatures.length <= 10^5
- 30 <= temperatures[i] <= 100

## 前期思路

### 朴素方法与复杂度

对每一天向右扫描，遇到第一项严格更高就停下，记下下标差。若一直扫描到末尾仍没找到，答案为零。这样非常容易手推，但温度持续下降时每一天几乎都要扫到最后，总时间O(n²)。

### 优化依据

换成时间向前推进的角度：每天到来时，检查它能帮助哪些还没等到答案的过去日期。已经找到答案的日期永久结束，不再参与。还没找到的日期只需要保存下标，以便既能读取温度又能计算等待距离。

### 算法推导

从左向右访问当前日i。让栈保存待解决的日期，栈底到顶的温度保持不升。为什么有这个顺序？若当前温度高于栈顶，栈顶已经等到答案，弹出并记录i减去它的下标；继续检查新的顶项，直到顶项温度不低于当前，或栈空，然后压入i。

只看栈顶为什么不会漏？顶项是最近的待办，若它已经不低于当前，则更早留在栈里的温度只会更高或相等，也不能被当前解决。若顶项能解决，弹出后才轮到更早待办。每个被弹出的日期此前一直留在栈中，说明它与当前之间没有遇到更高温度，因此当前正是第一天而非随便某个更暖日。

所有日期处理完，栈里剩下的没有未来更高温度，保留初始化的零。每个日期入栈一次、出栈最多一次，把全程动作相加就是线性，并非每个当前日都重新扫描全部历史。

### 变式分析与错误反例

- 若改成寻找后面第一个不低于当天的温度，把严格大于改成大于等于，并相应调整栈顺序的解释。若改为环形一年温度，需要遍历延长范围但只为原始日期入栈或控制重复，不能仅把数组接两遍就不管距离范围。
- 错误反例：`[70,70,71]`的答案是`[2,1,0]`。使用大于等于结算会把第一天答案误写成1。若栈只存温度，在两个70出现时又无法准确恢复各自日期。

## 执行过程示例

用`[73,71,72,74]`逐日手推，栈中写下标。

| 当前日与温度 | 结算 | 处理后栈 | 答案变化 |
| --- | --- | --- | --- |
| 0与73 | 无 | 0 | 全零 |
| 1与71 | 不能解决73 | 0 1 | 不变 |
| 2与72 | 弹1 | 0 2 | 第1日等1天 |
| 3与74 | 弹2 再弹0 | 3 | 第2日等1天 第0日等3天 |

得到`[3,1,1,0]`，最后一天无需额外弹栈填值。

## 解法复述与检查

- 栈里保存的是全部历史还是未解决日期？
- 为什么存下标？
- 相等温度为什么不弹出？

:::details 算法概述

将还没等到更暖天气的日期放在栈里。新一天到来时，只要它比栈顶更暖就结算这个日期的等待距离，持续弹出可解决的日期，然后把今天加入。留下的温度不升，所以栈顶不能解决时更早日期也不能解决。每个被结算的日期首次遇到更暖天气，答案就是最近距离。

:::

## TypeScript 实现

```ts
export function dailyTemperatures(temperatures: number[]): number[] {
  const answer = Array<number>(temperatures.length).fill(0)
  const waiting: number[] = []
  for (let day = 0; day < temperatures.length; day++) {
    // 栈中只保留尚未等到严格更高温度的日期
    while (waiting.length > 0 && temperatures[day] > temperatures[waiting[waiting.length - 1]]) {
      const previous = waiting.pop()!
      answer[previous] = day - previous
    }
    waiting.push(day)
  }
  return answer
}
```

## 复杂度与边界

- 时间**O(n)**，总共n次入栈与至多n次出栈。
- 辅助栈最坏**O(n)**，返回数组另占**O(n)**。
- 不修改输入。
- 相等和单调下降都可能让栈很长，它们仍是合法输入而非异常。
