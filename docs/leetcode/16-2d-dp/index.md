# 多维动态规划基础 状态坐标与依赖顺序

阅读前提：[动态规划基础](/leetcode/15-dp/)。多维状态用于描述需要多个独立参数才能确定的子问题。位置在一条线上只需一个下标，位置在网格里需要行与列；比较两个字符串的前缀需要各自的长度；判断一段字符串需要左右端点。数组维数由描述子问题所需的信息决定。

## 三类状态的含义与区别

网格状态常表示到某个格子的数量或最优代价，它的依赖由移动方向决定。右下移动让当前格依赖上方与左方。两个字符串的状态常表示一对前缀之间的关系，它的依赖由是否保留各自末字符决定。区间状态描述左右端点围住的部分，依赖可能位于内部，不一定在普通扫描方向的左边或上边。

它们都画成表格，但表格形状相同不代表转移相同。不同路径把两个来源的数量相加，最小路径和在两个来源之间选便宜的；编辑距离比较操作成本，公共子序列比较匹配长度。合并操作由问题要求决定，不能根据上一题刚用了加法就照搬。

## 长度下标与位置下标

前缀表 length[i][j] 常把 i 和 j 当字符数量，因此下标零表示空前缀，实际末字符是字符串下标 i-1 和 j-1。这样空字符串边界能够统一放入表中。区间表 palindrome[left][right] 却把下标当实际字符位置，两个端点都包括，区间长度为 right-left+1。明确定义下标是长度还是位置，可以避免边界转换中的偏移错误。

## 顺序由依赖决定

在网格表里，若当前只读上方与左方，就可以从左上到右下按行计算。前缀比较同样读取更短前缀。回文区间读取去掉两端后的内部区间，因此按长度递增最容易解释。循环方向应由依赖关系决定。可将当前状态连接到它读取的旧状态，再安排这些旧状态先完成的计算顺序。

小例子 abc 对 ac 的公共子序列表，从空前缀的零开始，a与a相同得到1，ab与ac末尾不同继承1，abc与ac末尾相同从更短前缀的1加到2。每格仅依赖此前已经计算完成的状态，因此可按上述顺序单次填表。

## 初始化是最小问题的真实答案

不同路径第一行只有一路可走，所以是1。最小路径和第一行要累计格子权重，不能也填1。编辑距离空串到长度j的串需要j次插入，不能全填0。最长公共子序列任何一边为空没有字符可匹配，所以是0。初始化不同不是各题例外多，而是状态含义本来不同。

TypeScript 创建二维数组时，用 Array.from 为每行分别创建数组。把同一个数组填进所有行会共享引用，写一个格子会同时影响别的行。这个错误与前端浅拷贝问题同源，但在动态规划里会直接篡改历史答案。

## 空间压缩的前提

如果只读上一行和本行左侧，可以把二维表压成一行，但必须辨认某个变量在更新前属于上一行还是当前行。左上角旧值可能被覆盖，需要临时保存。空间压缩前应先明确完整表的逐格计算过程。若要恢复具体路线或操作，完整来源记录常常比少一行空间更重要。

## 失效与复杂度

每格常数次工作时，m乘n个状态意味着O(mn)时间和表空间；若每格还枚举切点，时间要额外乘那层工作。允许网格反向移动可能产生循环依赖，不能继续使用一次从左上到右下填表。状态只记代价而规则又依赖进入方向，也会丢掉必要历史。这些条件变化要求重新检查子问题定义与依赖关系，再确定转移和计算顺序。
