# 二分查找基础 单调性与候选区间

相关基础：[复杂度与数据结构](/leetcode/00-intro/02-complexity-and-structures)。二分查找的依据是通过一次比较排除一整段不可能包含答案的候选。只有能证明被删部分不可能有答案，缩小范围才是可靠算法。

## 从逐个确认到整段排除

在递增数组 [1,3,5,7,9] 找 8，逐项比较可以确定目标是否存在。但看到中间的 5，就知道它左边不会有 8。这个结论依赖顺序，不依赖数组长度。下一次对剩下的一段做相同判断，直到找到或候选为空。每次大致减半，所以经过 k 次后候选约为原来的二的 k 次方分之一，由此得到对数时间。

对数效率来自每次舍弃固定比例，不是来自代码里出现除以二。若中点命中后仍左右扫描大量重复值，最坏时间仍可能线性。若不具备排序或其他单调信息，直接减半可能排除真实答案，算法不再正确。

## 区间约定与边界变量

闭区间 [left,right] 包含两端，初始可设为 [0,n-1]。当 left=right 时还有一个候选，目标查找继续执行，所以循环常用 left<=right。中点已确认不合格后，下一范围必须越过它，使用 mid+1 或 mid-1。

左闭右开 [left,right) 不包含右端，初始可设为 [0,n)。两端相等表示没有待查元素。寻找插入边界时，右端可以是数组长度，代表全部元素之后的位置，不能直接读取这个位置。区间约定决定终止条件和中点更新方式，三者必须保持一致。

还有一种闭区间算法一直保留答案，直到只剩一个候选，此时使用 left<right。寻找最小值就是例子。循环条件取决于终止时需要空区间还是唯一候选，不能在不同区间约定之间直接复用。

## 边界查找与普通命中不同

有重复值的数组 [1,2,2,2,4] 找到中间的 2，不代表找到了第一个 2。若要最早位置，就把条件写成值是否不小于 2，这些结果排列为假 真 真 真 真。查找的是真假交界，相等时还应保留更左位置。若找最后一个 2，可以找首个大于 2 的边界再减一。

这里的单调性是判断结果从某处起改变后不再反复。二分既可以用于有序元素，也可以用于具有这种判断结构的答案空间。但必须先证明单调，不能见到最小或最大就直接二分。

## TypeScript 实现细节

用 left + Math.floor((right-left)/2) 表示偏左中点。位运算会将数值转换为三十二位整数，因此中点计算使用 Math.floor 保留通用数值语义。判断查找结果时，应显式比较不存在标记，因为下标零也是合法结果。数组不会因为使用二分而自动排序，预先排序有时间成本，也可能丢掉题目需要的原下标。

## 最小手推与失效判断

在 [1,3,5] 找首个不小于 4 的位置：初始 [0,3)，中点1值3太小，左端变2；中点2值5合格，右端变2，返回2。只剩一个候选仍要判断它是否满足条件，而不能在长度为一时随意返回。

旋转数组整体无序，但能识别其中有序半段；两个有序数组的中位数可以查找切口，而不是查找某个值。这些题的共同点是解释整段排除，具体判定不能相互照搬。学习时每次写出候选含义、排除依据、是否保留中点和终止含义四句话。
