# 0035 搜索插入位置

相关基础：[本章基础](/leetcode/11-binary-search/)。题目来源：[力扣 35](https://leetcode.cn/problems/search-insert-position/)。

## 题目

:::info 题面

**难度**：简单

输入是递增且没有重复的整数数组和目标值。找到目标就返回下标，找不到就返回插入后仍有序的位置。数组至少有一个元素。答案允许等于数组长度，那表示插在最后，不是越界访问的请求。比如 [1,3,5,6] 找 2，要返回 1，因为它应放在 1 和 3 之间。

:::

### 官方示例

> **示例 1**
>
> 输入: nums = [1,3,5,6], target = 5
> 输出: 2

> **示例 2**
>
> 输入: nums = [1,3,5,6], target = 2
> 输出: 1

> **示例 3**
>
> 输入: nums = [1,3,5,6], target = 7
> 输出: 4

### 约束

- 1 <= nums.length <= 10^4
- -10^4 <= nums[i] <= 10^4
- nums 为 无重复元素 的 升序 排列数组
- -10^4 <= target <= 10^4

## 前期思路

### 朴素方法与复杂度

从左向右读，遇到第一个不小于目标的元素就停。此前的数都更小，因此这个位置正好能放目标；如果一直没有遇到，就放末尾。该方法的时间为 O(n)。将任务定义为查找第一个不小于目标的位置，便可统一目标存在和不存在的情况。

### 优化依据与所需信息

扫描逐个确认哪些数更小，但有序性实际上让一次比较携带整段信息。中间位置的数如果小于目标，它左边所有数也小于目标，整段都不可能是所求边界；中间数如果大于等于目标，它右边不可能比它更早，答案只能在它自己或左边。省下的不是重复加法，而是没有必要逐个验证的候选。

由此需要维护一个仍有可能包含答案的搜索范围。使用左闭右开区间 [left,right)，初始为 [0,n)。区间之外保证左侧全小于目标，右侧全大于等于目标。右端 n 是一个合法插入位置，虽然它不对应实际元素。

### 算法推导

取中点 mid。如果 nums[mid] 小于目标，中点自己也不合格，所以 left 移到 mid+1。如果 nums[mid] 大于等于目标，中点可能就是答案，不能把它排除在最终插入位置之外；令 right=mid，把更右候选排除。这里右开区间不保存 mid 作为下一次读取候选，但保留它作为边界位置，所以最后可以返回它。

每一步比较后，左边已确认小于目标的事实和右边已确认不小于目标的事实仍成立。区间长度严格缩短，最终 left=right，两个区域恰好在此交界。这个位置之前没有合格元素，它自己若存在则合格，因此就是所求第一个位置。这才是返回 left 的原因，不是二分题一律返回左变量。

### 变式分析与错误反例

- 若允许重复，本实现仍返回第一个不小于目标的位置，也就是插在相等元素之前。若要求插在所有相等元素之后，则中点等于目标时也要往右，边界定义变成第一个大于目标的位置。错误做法是明明要最早相等位置，却在相等时令left=mid+1，这会越过应保留的候选。例如[2,2,2]查找2时，正确返回0，该错误规则却会返回3。必须从需求决定相等时的方向，而不是记住某个符号。
- 若数组无序，[5,1,3] 中值为 1 并不能证明左边都小于 2。二分失效的根本原因是整段排除没有依据，不是实现少了一个判断。

## 执行过程示例

输入 [1,3,5,6]，目标 2。

| 左右边界 | 中点和值 | 判断依据 | 新边界 |
| --- | --- | --- | --- |
| 0 和 4 | 2 对应 5 | 5 不小于 2 保留更早边界 | 0 和 2 |
| 0 和 2 | 1 对应 3 | 3 不小于 2 继续向左 | 0 和 1 |
| 0 和 1 | 0 对应 1 | 1 小于 2 排除下标 0 | 1 和 1 |

搜索结束返回 1。若目标为 7，每次中点都太小，左边界最终成为 4。返回 n 表示在全部元素之后插入，将它截断为 n-1 会改变插入位置。

## 解法复述与检查

复述检查：

- 目标不存在时，为什么仍可使用同一规则？
- 遇到相等值时为什么仍然可以收缩右端？
- 终止后两个区域各有什么性质？

:::details 算法概述

将任务变成寻找第一个不小于目标的边界。中点小于目标时，中点和它左侧都不能作为答案；否则答案不会在中点右边。不断缩小左闭右开的范围，直到左右相遇，此时左侧全小于目标，右侧全不小于目标，交界就是插入位置。

:::

## 复杂度与边界

- 每轮范围大致减半，时间 **O(log n)**，辅助空间 **O(1)**，没有递归栈，不修改输入。
- 目标小于最小值返回 0，大于最大值返回 n，相等返回该元素下标。
- 用 Math.floor 求中点，不使用会把数字截为三十二位整数的位运算技巧。
- 题目整数范围内比较精确。

## 分层提示

:::details 提示一 观察方向

想象从左向右找第一个不小于目标的元素 插入位置是否就是它

:::

:::details 提示二 需要的信息

有序数组中 中点过小时 哪些位置可以一起排除

:::

:::details 提示三 组织步骤

维护左闭右开范围 中点小于目标就让左端越过中点 否则右端改为中点 相遇返回左端

:::

## TypeScript 实现

本地使用命名导出供测试调用 提交力扣时按题目入口移除导出声明

```ts
export function searchInsert(nums: number[], target: number): number {
  // 左侧已确认更小而右侧已确认不小于目标
  let left = 0
  let right = nums.length
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2)
    if (nums[mid] < target) left = mid + 1
    else right = mid
  }
  // 交界允许位于数组末尾之后
  return left
}
```
