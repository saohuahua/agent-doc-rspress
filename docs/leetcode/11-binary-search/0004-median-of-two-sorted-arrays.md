# 0004 寻找两个正序数组的中位数

相关基础：[本章基础](/leetcode/11-binary-search/)。题目来源：[力扣 4](https://leetcode.cn/problems/median-of-two-sorted-arrays/)。

## 题目

:::info 题面

**难度**：困难

两个非递减整数数组分别长 m 和 n，其中一个可以为空，但总长度至少为一。要求把所有数放在一起后的中位数：总数为奇数取中间元素，为偶数取中间两个数的平均值。目标时间是 O(log(m+n))，所以真实合并再找中间只能作为起点，不能作为最终满足要求的解法。

:::

### 官方示例

> **示例 1**
>
> 输入：nums1 = [1,3], nums2 = [2]
> 输出：2.00000

> **示例 2**
>
> 输入：nums1 = [1,2], nums2 = [3,4]
> 输出：2.50000

### 约束

- nums1.length == m
- nums2.length == n
- 0 <= m <= 1000
- 0 <= n <= 1000
- 1 <= m + n <= 2000
- -10^6 <= nums1[i], nums2[i] <= 10^6

## 前期思路

### 朴素方法与复杂度

分别维护两数组的当前下标，每次拿较小值，像归并一样把所有元素排好，最后读中间位置。时间 O(m+n)，复制完整结果还要 O(m+n) 空间。只走到中间并保留最后两项可以省空间，但时间仍然线性。实际需要的不是完整排序，而是中间两侧的边界。

### 从合并转向划分

假设能把全部元素分成左半和右半，并保证左半每个数不大于右半每个数。左半固定拿 floor((m+n+1)/2) 个，让奇数时多出的一个留在左边。此时中位数只由左半最大值和右半最小值决定。

两个原数组已经有序，每个数组分给左半的元素都必须是一个前缀。设较短数组 A 贡献 i 个，另一个 B 贡献 j 个，则 j=half-i。需要猜的其实只有一个位置 i，不必同时猜两个划分点。选择短数组长度 m<=n，i 可以在 0 到 m 之间，计算出的 j 自动位于 0 到 n 之间，避免越界猜测。

### 合法划分条件

把切口两边的邻居记为 Aleft=A[i-1]、Aright=A[i]、Bleft=B[j-1]、Bright=B[j]。切口在端点时相应一侧为空，用负无穷表示空左侧，用正无穷表示空右侧。这些是比较用哨兵，不是真把无穷写入输入。

数组内部已满足左边不大于右边，只需检查跨数组的两条关系：Aleft<=Bright 且 Bleft<=Aright。两条都成立，就能保证合并后的所有左半元素不大于所有右半元素。左半数量又恰好正确，因此划分合法，不需要知道各半区内部的完整归并顺序。

### 折半调整依据

如果 Aleft>Bright，A 给左边的元素太多。增加 i 会让 Aleft 不减，同时 j 变小会让 Bright 不增，只会更坏，因此当前 i 和所有更大位置都可排除，应向左找。

如果 Bleft>Aright，A 给左边的元素太少。减小 i 会让 Aright 不增，同时 j 增大使 Bleft 不减，也不会修好，应向右找。两类不合法情况不可能同时成立，因为那会与各数组内部顺序矛盾。合法划分必然存在：想象真实合并结果取前 half 个，它自然对应两个前缀。

因此维护 i 的闭区间 [0,m]，每次取中点，根据上述跨边界比较舍弃一半。找到合法划分时，奇数返回 max(Aleft,Bleft)；偶数返回这个最大值与 min(Aright,Bright) 的平均。总长非零保证需要的中间实际元素存在，哨兵不会作为最终中位数留下。

### 变式分析与错误反例

- 错误办法是取两个数组中位数的平均：[1,2] 与 [3,4,5,6] 各自中位数为1.5和4.5，平均3，但合并中位数为3.5，因为两组大小不同，局部中位数丢掉了排序位置。若求第 k 小，可以把左半数量改成 k，但 i 的合法区间要改为 max(0,k-n) 到 min(k,m)，不能机械保留全部切口。若输入未排序，跨边界关系不再足以保证半区大小关系。

## 执行过程示例

A=[1,2]，B=[3,4]，half=2。

| i 和 j | 四个邻居 | 判断 | 下一步 |
| --- | --- | --- | --- |
| i=1 j=1 | 1 2 3 4 | Bleft为3大于Aright为2 | A左半太少 i向右 |
| i=2 j=0 | 2 正无穷 负无穷 3 | 两条跨边界关系都成立 | 左最大2 右最小3 |

总数为偶数，答案为 2.5。空数组例子 A=[]、B=[1] 时，唯一切口 i=0、j=1，A 两个邻居是哨兵，左最大为1，直接得到答案。代码不用为这一情形复制另一套算法。

## 解法复述与检查

- 先说数量条件，再说大小条件。为什么不需要合并？
- 为什么只对短数组的切口查找？
- 为什么 Aleft 太大时必须减小 i？

:::details 算法概述

只寻找把所有数分成正确数量的左右两半的切口。短数组取 i 个放左边，长数组取 half-i 个。两个数组内部有序，所以只验证交叉边界。短数组左邻居过大就少取一些，长数组左邻居过大就让短数组多取一些。合法后左最大和右最小就给出中位数，整个过程不构造合并数组。

:::

## 复杂度与边界

- 时间 **O(log(min(m,n)**+1))，满足题目对数要求；辅助空间 **O(1)**，无递归栈，不修改输入。
- 用局部引用交换保证 A 较短，没有复制数组。
- 重复元素用非严格比较处理。
- 负数、单数组为空、奇偶总长均由同一划分处理。
- 题目数值范围内中间两数求和精确，推广到极大整数时需要重新设计数值表示。

## 分层提示

:::details 提示一 观察方向

中位数只关心左右两半的交界 不要求实际列出合并顺序

:::

:::details 提示二 需要的信息

固定左半总数量 一个数组的贡献确定后 另一个就确定 检查四个切口邻居

:::

:::details 提示三 组织步骤

对短数组贡献数量折半搜索 左邻居太大就少取 太小导致对侧越界就多取 合法后读取边界值

:::

## TypeScript 实现

本地使用命名导出供测试调用 提交力扣时按题目入口移除导出声明

```ts
export function findMedianSortedArrays(nums1: number[], nums2: number[]): number {
  // 只交换引用以保证搜索短数组的全部切口都合法
  let a = nums1
  let b = nums2
  if (a.length > b.length) [a, b] = [b, a]
  const half = Math.floor((a.length + b.length + 1) / 2)
  let left = 0
  let right = a.length
  while (left <= right) {
    const i = left + Math.floor((right - left) / 2)
    const j = half - i
    // 空半区通过无穷哨兵参与统一比较
    const aLeft = i === 0 ? -Infinity : a[i - 1]
    const aRight = i === a.length ? Infinity : a[i]
    const bLeft = j === 0 ? -Infinity : b[j - 1]
    const bRight = j === b.length ? Infinity : b[j]
    if (aLeft > bRight) right = i - 1
    else if (bLeft > aRight) left = i + 1
    else {
      const lower = Math.max(aLeft, bLeft)
      if ((a.length + b.length) % 2 === 1) return lower
      return (lower + Math.min(aRight, bRight)) / 2
    }
  }
  throw new Error('输入必须为有序数组且总长度非零')
}
```
