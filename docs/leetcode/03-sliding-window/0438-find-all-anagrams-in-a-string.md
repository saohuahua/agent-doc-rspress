# 0438 找到字符串中所有字母异位词

阅读前提：[本章基础](/leetcode/03-sliding-window/)。[官方题目](https://leetcode.cn/problems/find-all-anagrams-in-a-string/)。

## 题目

:::info 题面

**难度**：中等

给字符串 s 和非空字符串 p，在 s 中找所有与 p 字母组成相同的连续片段，返回起始下标。输入仅含小写英文字母。例如 s 为 cbaebabacd，p 为 abc，答案是 [0,6]，对应 cba 和 bac。字母顺序可以不同，次数必须相同，片段必须连续。

先读[哈希基础](/leetcode/01-hash/)了解计数表。本题与字母异位词分组共享“字母和次数决定身份”的事实，但这里候选来自一个字符串中的连续位置，不是独立单词列表。

:::

### 官方示例

> **示例 1**
>
> 输入: s = "cbaebabacd", p = "abc"
> 输出: [0,6]

> **示例 2**
>
> 输入: s = "abab", p = "ab"
> 输出: [0,1,2]

### 约束

- 1 <= s.length, p.length <= 3 * 10^4
- s 和 p 仅包含小写字母

## 前期思路

### 朴素方法与复杂度

p 长度为三，就检查 s 中每个长度三的片段。将每段排序后和排序后的 p 比较，是一个清楚的正确方案。长度为 m，每次复制排序 O(m log m)，大约 n 个起点，总时间 O(nm log m)。

还可以对每段数出 26 个字母的次数再比较，避免排序，但每次仍从头统计 m 个字符，时间 O(nm)。尝试次数不能省掉，因为要返回全部起点；可以省掉的是相邻片段重复统计的过程。

### 优化依据

长度三的 abc 与下一段 bcd 共享 b 和 c。离开的只有 a，加入的只有 d。既然中间两项的次数没变，直接从旧计数减去 a，再加上 d，就得到了下一窗口的计数。

p 的目标次数固定不变，只算一次。当前窗口次数随着两端移动更新。小写字母只有 26 种，用长度 26 的数组即可；a 对应位置零，b 对应位置一。这样不需要为每一段重新创建字符串，也不需要 Map 保存任意键。

### 算法推导与正确性

右端从零开始，每次加入当前字符。若已超过 p 的长度，就移除下标 right - p.length 的字符。于是窗口只保留最近 m 个字符。前 m - 1 步尚未凑够长度，不比较；从第 m 个字符起，逐项比较两张计数表。

计数比较的充分性与必要性如下：窗口长度固定为 m，且每种字母次数相同，意味着正好包含 p 的全部字母，没有遗漏也没有多出。反过来，如果是异位词，每个字母次数必相同。因此这个判断既不会误收，也不会漏收。

每个可能的长度 m 子串都由唯一的右端位置确定。算法访问所有右端，对每个长度足够的窗口判断一次，因此覆盖全部起点。输出起点是 right - m + 1，不能写成 right - m，否则会少一位。

### 变式分析与错误反例

- 只比较集合会把 aab 与 abb 当成匹配，因为两者都出现 a 和 b，却少了一个 a、多了一个 b。只比较窗口字符是否都属于目标集合也不够，道理相同。
- 如果字母种类不固定为 26，改用 Map 计数，并考虑比较全部键的成本；也可维护尚未匹配的种类数，但更新必须准确处理从相等变为不等和恢复相等的边界。初学时优先使用本题 26 项比较，清晰且已经线性。
- 如果题目改成找包含 p 全部字符的最短片段，窗口长度不再固定，计数允许多余，应该重新推导扩张和收缩规则，参见最小覆盖子串，不能继续每次强行保持 m 项。

## 执行过程示例

s 为 abab，p 为 ab，目标计数 a 一次、b 一次。

| 右端 | 加入与移除 | 当前窗口 | 计数结果 | 输出 |
| --- | --- | --- | --- | --- |
| 0 | 加入 a | a | 尚未达到长度二 | 空 |
| 1 | 加入 b | ab | a 与 b 各一次 | 0 |
| 2 | 加入 a 移除位置 0 的 a | ba | 计数保持匹配 | 0 和 1 |
| 3 | 加入 b 移除位置 1 的 b | ab | 仍然匹配 | 0 和 1 和 2 |

相邻答案允许重叠。不能找到第一段后跳过整个长度，否则会漏掉起点 1。

## 解法复述与检查

- 为什么窗口长度固定？
- 相邻候选变化了什么？
- 只有字母集合相同是否足够？

:::details 解法概述

先统计目标字符串的字母次数，再维护长度等于目标的连续窗口。右端加入一个字符，超过目标长度时移除最左字符，复用中间字符的计数。窗口长度足够后比较两张计数表，完全一致时记录起点。每次只移动一格，因此重叠答案也会被检查。

:::

## TypeScript 实现

```ts
export function findAnagrams(s: string, p: string): number[] {
  const result: number[] = []
  if (p.length > s.length) return result
  const need = new Array<number>(26).fill(0)
  const window = new Array<number>(26).fill(0)
  const indexOf = (char: string) => char.charCodeAt(0) - 97
  for (const char of p) need[indexOf(char)]++
  for (let right = 0; right < s.length; right++) {
    window[indexOf(s[right])]++
    // 超出固定长度时移除刚离开左侧的字符
    if (right >= p.length) window[indexOf(s[right - p.length])]-- // [!code highlight]
    if (right >= p.length - 1 && window.every((count, index) => count === need[index])) { // [!code highlight]
      result.push(right - p.length + 1)
    }
  }
  return result
}
```

## 复杂度与边界

- 每个字符常数次更新，每个候选比较 26 项，时间 **O(m + 26n)**，固定字母表下写 **O(n + m)**。
- 两张长度 26 的数组为 **O(1)** 辅助空间，输出 k 个起点占 **O(k)**。
- 不修改输入，无递归。
- p 比 s 长时直接返回空数组。
- p 非空是本题前提，代码不定义空模式匹配语义。
