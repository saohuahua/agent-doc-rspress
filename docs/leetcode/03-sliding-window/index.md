# 03 滑动窗口基础

连续区间问题的分析包括三个方面：区间由什么条件限定、加入元素如何改变状态、调整边界能否复用已有信息。本章据此建立窗口维护方法及其适用条件。

## 连续区间与端点约定

数组 `[2, 5, 1, 4]` 中 `[5, 1]` 是连续子数组，`[2, 1]` 跳过了 5，属于子序列而不是子数组。字符串也一样，子串要求连续，子序列允许跳过。连续区间可由两个端点完整确定，因此不必为每次尝试真的复制一个新数组。

本章默认用闭区间 `[left, right]`，两端都属于区间，长度是 `right - left + 1`。闭区间只是约定；也可以采用右开区间，但长度公式和循环条件必须一起变化，不能混着写。前端中的 `slice(start, end)` 使用右端不包含的约定，取出闭区间时要写成 `slice(left, right + 1)`。

## 从枚举到复用信息

最直接的方法是尝试每个起点和终点。n 个位置有 `n(n + 1) / 2` 个非空连续区间，仅逐个尝试就已经是 O(n²)。但相邻区间往往只差一个元素，如果每次都重新计算内容，会做更多重复工作。

例如求每段连续三个数字的和，`[2, 5, 1]` 的和是 8，下一段 `[5, 1, 4]` 无需重加三个数字，只需 `8 - 2 + 4 = 10`。**保留仍然有效的信息，减掉离开的元素，加上进入的元素**，就是窗口的基本动机。

固定长度窗口只需控制数量。可变长度窗口则先明确合法条件，例如字符不能重复，然后在右侧加入元素后，从左侧移除足够元素恢复条件。不同题目的恢复规则不同，不存在适合所有题的一份移动模板。

## 状态的含义

状态就是为了决定下一步而保存的信息。窗口左右端表示区间位置，计数表表示区间内容特征，历史最大值表示已处理候选的最优结果。状态职责不能混淆：当前窗口变短，不代表历史最大值要变小。

这一节需要先理解成员查询与键值关联，参见[哈希基础](/leetcode/01-hash/)。Set 只记录成员，Map 同时记录成员关联的信息。

TS 中可以用 `Set<string>` 判断某字符是否在当前窗口，用 `Map<string, number>` 记录次数或位置。虽然类型相同，次数表和位置表的含义完全不同。次数表需要在字符离开时扣减；全局最近位置表不一定删除旧条目，但必须用边界判断记录是否仍有效。

Map 的查询通常按平均 O(1) 分析，不代表 JavaScript 规范承诺所有实现严格常数时间。数组切片会创建新数组，反复 `slice` 再扫描可能让看似一次遍历的代码仍然很慢。分析复杂度要数实际操作，不能只数代码里有几层循环。

## 指针总移动次数与时间复杂度

假设右端从 0 走到 n，左端也只向右走，从不退回。尽管“每次右端移动后，左端可能循环移动多次”，整个执行过程中左端总共也最多移动 n 次，所以边界调整总次数是 O(n)。前提是每一步内部操作开销可控，而且左端不反复归零。

这个结论解释的是总次数，不是“两个循环写在一起也一定 O(n)”。如果每个右端都重新把左端从 0 扫一遍，总次数仍可能是平方。

## 边界移动的适用条件

无重复字符这一条件有两个重要性质：合法段删掉左侧字符后仍合法；包含重复的段只往右添加字符无法变合法。因此移除已经被证实不可能的起点是安全的。

上述结论依赖于合法性的单调变化，并不适用于所有连续区间。例如寻找和至少为 3 的最短子数组，若数字全为正，右扩使和增大，左缩使和减小；若允许负数，这种方向关系就可能失效。`[1, -1, 3]` 的总和达到 3，删去左侧 1 后和变成 2，但再删去 -1 会恢复为 3，得到更短的 `[3]`。套用只在和足够时继续收缩的规则会提前停止。

能否安全舍弃某些起点，必须从题目条件论证。题目包含“最长”“连续”，只值得把窗口作为候选，不能直接当成答案。

## 最小执行示例

对 `aba` 维护没有重复的区间：先得到 `a`，加入 `b` 后得到 `ab`；再加入 `a` 时发生冲突，移出旧 `a`，保留 `ba`。历史最大长度是 2。这里没有移除中间的 `b`，因为只需要排除造成冲突的旧 `a`，保留越多，越有机会得到长答案。

读者需要能解释三个问题：为什么只移动左端就能修复；为什么不把整个窗口清空；为什么历史最大不能直接等于最后窗口长度。这些问题构成后续题目的推导检查项。
