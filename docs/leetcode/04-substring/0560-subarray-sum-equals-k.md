# 0560 和为 K 的子数组

阅读前提：[本章基础](/leetcode/04-substring/)。[官方题目](https://leetcode.cn/problems/subarray-sum-equals-k/)。

## 题目

:::info 题面

**难度**：中等

返回和恰好为 k 的非空连续子数组数量，不是最长长度，也不是返回这些区间本身。数组允许正数、零、负数。例如 [1,1,1]、k 为 2，有两个不同位置区间，因此答案为 2，即使它们数值相同也分别计数。

先读[哈希基础](/leetcode/01-hash/)。本题要记录次数，因为多个不同起点可能对应同一个累计和，单个下标或存在集合会丢失答案数量。

:::

### 官方示例

> **示例 1**
>
> 输入：nums = [1,1,1], k = 2
> 输出：2

> **示例 2**
>
> 输入：nums = [1,2,3], k = 3
> 输出：2

### 约束

- 1 <= nums.length <= 2 * 10^4
- -1000 <= nums[i] <= 1000
- -10^7 <= k <= 10^7

## 前期思路

### 朴素方法与复杂度

固定左端，然后不断向右累加，每扩一个右端就检查当前和。这样每个连续区间都被检查一次，O(n²) 时间，O(1) 额外空间。若对每对端点都重新求和，会增加一层重复扫描，使时间退化为 O(n³)。

想用“和大了就收缩”也要先看约束。允许负数时，加入一个数可能减小和，移出一个数可能增大和，所以不能仅根据当前和与 k 的大小安全丢掉某些起点。

### 从重复求和到前缀差

把前 i 个元素之和记为 P[i]，其中 P[0] 是没有元素的空前缀，等于零。下标 left 到 right 的和，是 P[right + 1] 减 P[left]，因为前面的共同部分被抵消了。

固定当前累计和 P[right + 1]，想让区间和等于 k，就需要某个更早的 P[left] 等于当前累计和减 k。这与两数之和的补数变形类似：本来枚举所有起点，现在查询一个确定的历史数值。

但是历史中相同前缀值可能出现多次，每一次代表不同的起点，都应贡献一个区间。例如 [0,0]、k 为零，第一个零前后累计和都为零，第二个零结尾就能形成两个合法区间。因此要存“前缀和 → 出现次数”。

### 算法推导与正确性

先把空前缀零记录一次。逐个加入数组元素得到当前前缀，再查询当前前缀减 k 的历史次数，把它加入答案，最后记录当前前缀。

先查询后记录保证起点在当前元素之后的空区间不会被计入，特别是 k 为零时。如果先记录当前前缀，k 为零时就会将当前前缀与其自身匹配，额外计入长度为零的区间。

每个非空区间有唯一右端，处理这个右端时，它的左前缀一定已在表中，并且满足差值关系时被计入。每个历史前缀位置也只贡献这个对应区间，所以既不会漏掉，也不会重复计数。扫描完最后一个右端后即可结束。

### 变式分析与错误反例

- 不初始化空前缀，在 [2]、k 为 2 时会返回零；只保存 Set，在 [0,0] 中无法得到三个区间；先记录再查询，同样输入会多算空区间。
- 若改求和为 k 的最长区间，要保存每种前缀的最早下标，用当前下标减去它得到长度，而不是保存次数。若只求是否存在，则保存存在性可能足够，但仍须先查再记。这说明查询公式相似，表中值却由输出要求决定。

## 执行过程示例

输入 [1,-1,0]，k 为零，初始记录 0 出现一次。

| 当前值 | 当前前缀 | 要找的历史前缀 | 历史次数与新发现区间 | 累计答案 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 1 | 0 次 没有区间 | 0 |
| -1 | 0 | 0 | 1 次 对应 [1,-1] | 1 |
| 0 | 0 | 0 | 2 次 对应 [1,-1,0] 和 [0] | 3 |

第二行之后零前缀次数变为二，第三行才能一次加二。次数不是“是否见过”，而是合法起点的数量。

## 解法复述与检查

- 区间和为什么是两个前缀之差？
- 为什么要保存次数？
- 为什么初始零出现一次？

:::details 解法概述

用两个前缀之差表达连续区间的和。固定当前前缀后，合法起点对应的历史前缀等于当前前缀减 k，因此维护各历史前缀出现次数。初始记录一次空前缀零；每轮先累加当前元素，查询匹配次数并计入答案，再记录当前前缀。查询先于记录保证只计入非空区间。

:::

## TypeScript 实现

```ts
export function subarraySum(nums: number[], k: number): number {
  // 空前缀使从下标零开始的区间也能被计入
  const counts = new Map<number, number>([[0, 1]])
  let prefix = 0
  let answer = 0
  for (const value of nums) {
    prefix += value
    // 先查历史以排除长度为零的区间
    answer += counts.get(prefix - k) ?? 0 // [!code highlight]
    counts.set(prefix, (counts.get(prefix) ?? 0) + 1) // [!code highlight]
  }
  return answer
}
```

## 复杂度与边界

- 哈希表平均常数操作假设下时间 **O(n)**，额外空间 **O(n)**，无递归，不修改输入。
- 输出一个计数，最大可能 n(n + 1) / 2，题目规模内以及前缀数值均在 number 安全整数范围内。
- 全零且 k 为零是检查计数是否保留全部历史的关键边界。
