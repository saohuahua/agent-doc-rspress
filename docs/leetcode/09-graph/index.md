# 图论基础 关系建模与可达性

地图上的格子、课程之间的先修关系、字母构成的路径，看上去并不相似。但它们都可以问同一个问题：一个对象和哪些对象直接相连，从这里沿连接能到哪里。

相关基础：[递归与引用](/leetcode/00-intro/03-ts-runtime-and-recursion) 和 [复杂度](/leetcode/00-intro/02-complexity-and-structures)。下文从顶点、边和访问顺序说明队列与栈的用途。

## 顶点与边的定义

图用顶点表示对象，用边表示关系。网格中每个格子可以是顶点，上下左右可走的相邻关系可以是边。若只能从课程A指向依赖它的课程B，边有方向；无向道路可以双向通行。格子斜对角不属于上下左右相邻，必须按题目定义连边。

图不一定画成圈，也不一定真的创建节点对象。网格可以直接通过坐标计算邻居。一般图可以用邻接表，数组的第u项保存从u能直接到达的顶点。存储空间为点数加边数，不必创建点数平方大小的表。

## 访问标记与重复到达

A连B、B又连A。如果访问A后继续访问B，又从B访问A，不记历史就会反复绕圈。发现一个点准备放入待处理容器时就标记，可以保证它最多加入一次。若等取出后才标记，多个邻居可能重复放入同一点，造成重复工作。

无向图中的连通分量是内部彼此可达的极大顶点集合，即再加入集合外顶点就无法保持内部全部可达。遍历到一个尚未访问的点，就从它出发访问能到的全部点，等这次搜索结束再找下一处未访问点。岛屿数量就是按陆地的上下左右连接统计这些组。

## 深度优先与广度优先

用栈保存待访问位置，每次取最近发现的点，可以先沿一条路深入，再处理分支，这叫深度优先。用队列保存待访问位置，每次处理最早发现的点，可以先处理距离起点近的一层，再处理下一层，这叫广度优先。

从A同时连接B与C，B又连接D。队列顺序是A、B、C、D；栈可以是A、C、B、D。两者都能判断能否到达，但若每条边的代价都是一步，分层顺序才能直接让第一次到达对应最少步数。边权不同后，首次到达不再保证累计代价最小，需要采用适合加权图的算法。

前端数组可以用push和pop做栈。队列使用数组加head下标读取，不反复shift。一次遍历仍可能保留已处理元素，空间分析要按整个数组容量计算，不能只看剩余队列长度。

## 多源传播与依赖消除

多个起点同时传播时，先把全部起点放入同一队列，它们都属于第零层。逐个起点各自完成搜索再合并时间，不能表达同时发生的过程。

课程依赖则需要记住每门课尚未完成的先修课数量，这叫入度。入度为零才可学习，学完后减少后继课程的入度。如果还有课程却找不到入度为零的入口，剩余依赖中存在环。不是所有图题都靠同一份访问模板。

## Trie 与共享前缀

字符串集合也可以形成树状连接。根不对应字母，每条边对应下一个字母，同前缀单词共享前面路径。路径存在只证明前缀存在，完整单词还需要结束标记。节点的Map保存字母到子节点的关系，这是一个专门适合逐字符查询的结构。

图的建模应明确顶点、边、方向和重复到达规则。这些定义决定邻居生成方式、访问标记和遍历次序，随后才能选择深度优先或广度优先搜索。
