# 0994 腐烂的橘子

多颗腐烂橘子会同时感染邻居。难点不是找到相邻格子，而是不能让刚感染的橘子在同一分钟里无限接着传播。

相关基础：[本章基础](/leetcode/09-graph/)。[力扣原题](https://leetcode.cn/problems/rotting-oranges/)。

## 题目

:::info 题面

**难度**：中等

网格中0为空，1为新鲜，2为腐烂。每分钟，所有腐烂橘子使上下左右相邻的新鲜橘子腐烂。返回全部橘子腐烂的最少分钟数；存在永远无法感染的新鲜橘子返回负一；起初没有新鲜橘子返回零。

:::

### 官方示例

> **示例 1**
>
> 输入：grid = [[2,1,1],[1,1,0],[0,1,1]]
> 输出：4

> **示例 2**
>
> 输入：grid = [[2,1,1],[0,1,1],[1,0,1]]
> 输出：-1

> **示例 3**
>
> 输入：grid = [[0,2]]
> 输出：0

### 约束

- m == grid.length
- n == grid[i].length
- 1 <= m, n <= 10
- grid[i][j] 仅为 0、1 或 2

## 前期思路

### 朴素方法与复杂度

最直观是每分钟复制一份网格，扫描旧网格中所有腐烂橘子，把它们的新鲜邻居写入新网格。整轮完成才切换网格，这样符合同时发生的要求。如果需要T分钟，反复扫描整张地图要O(Tmn)。这是一种可用的对照方案，但传播边界很小时仍重查所有旧格子。

### 优化依据

旧腐烂橘子周围已经没有新的可感染位置，再检查它们无益。下一分钟只需要处理这一分钟刚腐烂的橘子。于是把待传播的坐标按发现先后排好，并把每一轮开始时已有的数量作为本分钟的范围。所有初始腐烂橘子一起进入，不能只选其中一颗。

### 算法推导

扫描网格得到新鲜总数fresh，并将所有2加入同一队列。它们都对应时间零的传播源。若fresh已经为零，无需过一分钟。

一轮开始记下队列当前末尾end，只处理head到end之前的位置。新感染者追加到末尾但不在本轮处理。每发现一个1，立即改为2并减少fresh，防止同一分钟由两颗邻居感染时被重复计数。处理完本层才增加分钟数。

为什么得到最少时间？每条相邻传播都恰好花一分钟。第零层是所有初始源，第一层是距离某个源一步的橘子，随后每层扩展一步。若某格能更早被感染，它就应该邻接更早的一层，并已被发现，矛盾。若队列耗尽fresh仍大于零，这些新鲜橘子与所有源之间没有可传播路径，因此无解。

### 变式分析与错误反例

- 若问题改为每格到最近传播源的距离，队列中携带或另表记录层数即可。若不同橘子感染耗时不同，按层计时不再成立，需要按累计最早时间选择下一个传播位置。
- 错误反例：边扫描边直接感染并继续扫描 `[2,1,1]`，可能把两个新鲜橘子都算作第一分钟腐烂；真实答案是2。这说明遍历顺序不能替代同时传播的时间定义。

## 执行过程示例

用单行 `[2,1,1]` 看清层边界。

| 时间 | 本轮传播者 | 本轮新感染 | fresh | 理由 |
| --- | --- | --- | --- | --- |
| 0 | 位置0入队 | 尚未传播 | 2 | 初始腐烂不计耗时 |
| 1 | 只处理位置0 | 位置1入队 | 1 | 新入队位置不在固定end内 |
| 2 | 只处理位置1 | 位置2入队 | 0 | 下一分钟才继续传播 |

此时立即返回2，无须再处理已无新鲜邻居的位置2。

## 解法复述与检查

- 为什么每轮要先保存end？
- 多个腐烂起点为什么一起放入？
- 什么情况返回零或负一？

:::details 算法概述

先数新鲜橘子，把全部初始腐烂橘子加入队列。每轮只处理轮开始时已有的节点，新感染者标记并排到下一轮。完成一轮增加一分钟，直到新鲜数变零。若传播停止还有新鲜橘子就返回负一；初始没有新鲜的则是零分钟。

:::

## TypeScript 实现

```ts
export function orangesRotting(grid: number[][]): number {
  if (grid.length === 0 || grid[0].length === 0) return 0
  const rows = grid.length
  const cols = grid[0].length
  const queue: number[] = []
  let fresh = 0
  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (grid[r][c] === 1) fresh++
      else if (grid[r][c] === 2) queue.push(r * cols + c)
    }
  }
  let head = 0
  let minutes = 0
  const directions = [[1, 0], [-1, 0], [0, 1], [0, -1]]
  while (head < queue.length && fresh > 0) {
    // 固定本分钟的传播边界 新感染者留到下一分钟
    const end = queue.length
    while (head < end) {
      const current = queue[head++]
      const r = Math.floor(current / cols)
      const c = current % cols
      for (const [dr, dc] of directions) {
        const nr = r + dr
        const nc = c + dc
        if (nr < 0 || nr >= rows || nc < 0 || nc >= cols || grid[nr][nc] !== 1) continue
        // 立刻标记确保每颗新鲜橘子只计数一次
        grid[nr][nc] = 2
        fresh--
        queue.push(nr * cols + nc)
      }
    }
    minutes++
  }
  return fresh === 0 ? minutes : -1
}
```

## 复杂度与边界

- 每格至多加入队列一次，时间**O(mn)**，队列空间**O(mn)**，修改输入网格。
- 测试若要复用输入，应逐行复制。
- 初始有新鲜但无腐烂时队列为空，直接返回负一；空格不需要被感染。
