# 双指针基础

## 指针的含义与职责

在这些数组题里，指针通常只是一个保存下标的整数，不是 C 语言内存指针。它指示当前观察的位置、下一次写入的位置，或者尚未排除区域的边界。两个指针并没有统一的移动模板，必须先给每个位置一个明确职责。

阅读前先掌握[入门基础](/leetcode/00-intro/)中的数组下标与引用。数组写入会改变原对象；给局部变量赋一个新数组则不会改变调用者持有的原引用。“原地”说的是额外空间不随规模增长，通常允许几个临时变量，不意味着只能用一行表达式。

## 同向指针：读取与写入职责

移动零时 read 逐项查看输入，write 指向下一个非零值应该放的位置。它们都往右，但 read 每次移动，write 只有遇到要保留的值才移动。以 [0,2,0,3] 为例，读到 2 时写入位置零，读到 3 时写入位置一。已经写好的前缀总是已读内容去零后的结果。

安全性来自 write 不会越过 read，所以不会覆盖未来尚未读取的数据。如果任务要求向右搬运，读取方向可能必须反过来，例如数组整体右移时从左往右覆盖就危险。遍历方向必须保证写入位置不破坏后续读取所需的数据。

## 相向指针：候选范围的排除

有序数组找目标和时，左边小、右边大。和偏小时，固定左值换任何更小右值都不会成功，因此移走左端安全；和偏大则对称移右端。这里的方向来自有序性，乱序数组不具备这种排除依据。

盛水容器虽然输入无序，也能用两端指针，但证明不同：短边限制水面，保留短边而缩宽不会超过当前面积，所以可以删短边。看到两段代码形式相似，不代表它们使用了同一条性质。解法复述需要给出当前题目中排除某一端的具体依据。

## 指针总移动次数与时间复杂度

如果左端总共只前进 n 步，右端总共只前进 n 步，即使写成嵌套 while，总移动量也只有 O(n)。反之，如果外层每次都把内层指针重置，再完整扫描，就可能 O(n²)。三数之和固定首数后重新运行一轮双指针，所以总时间是 O(n²)，不能只看到内层两端单向移动就写 O(n)。

排序也需要计入。TS 数字排序必须传比较器，默认排序按字符串次序，10 可能排到 2 前面。sort 会修改原数组，若要求保留输入，应先复制。复制外层数字数组已足够，但二维数组还要检查内层引用。

## 边界与结果信息

闭区间 [left,right] 的元素数量是 right - left + 1，但两根线之间横向距离是 right - left。长度公式来自题意，不是看到两指针就加一。两端必须指向不同位置的配对，循环用 left < right；允许检查单个元素的任务则可能用小于等于。

当前候选与历史最优要分开保存。移动短边后当前面积可能下降，但历史答案不能跟着下降。同样，处理重复值要看输出要求：返回数值组合时可跳过重复结果，返回所有位置组合时不能随意丢掉同值的不同位置。

## 算法分析要点

算法推导需要明确三个方面：当前两个位置分别代表什么；本轮能确定哪部分已经正确或不再可能；移动以后这个解释为什么仍成立。接雨水主解先用前后最大值建立逐列水量依据，理解后再考虑两个边界压缩空间，分类用于组织知识，不限定唯一实现方式。
