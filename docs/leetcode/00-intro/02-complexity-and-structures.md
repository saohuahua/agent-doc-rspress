# 复杂度与数据结构

算法复杂度描述计算资源需求随输入规模增长的变化。即使两个程序在小规模输入上都能得到正确结果，其操作数量也可能以不同速度增长，从而决定它们能够处理的规模。

## 时间复杂度与操作计数

令 n 表示数组长度。扫描一次做 n 次比较，记作 O(n)。枚举所有不同数对要做 n 乘以 n 减一再除以二次检查，忽略常数和低阶项后是 O(n²)。它们不是精确秒数，而是输入规模增长时的数量级。

二分每次把剩余范围约减半。从 16 项变成 8、4、2、1，只需几次决策，次数随 log₂n 增长，记为 O(log n)。排序常见分析为 O(n log n)，但具体实现与输入特点仍会影响实际耗时。

| 做法 | n 为 1000 时的数量级 | 理由 |
| --- | --- | --- |
| 全扫描 | 1000 | 每项看一次 |
| 所有数对 | 约 50 万 | 每项与后面的项配对 |
| 折半查找 | 约 10 | 连续十次减半 |

循环嵌套层数不足以直接确定复杂度。如果内层右指针只向右移动且从不重置，它在全部外层迭代中累计最多移动 n 步，两指针的总工作量仍可能为 O(n)。反之，一层循环中若每次复制长度为 n 的数组，复制操作就可能使总时间达到 O(n²)。

## 辅助空间与输出空间

复制整个输入需要 O(n) 额外空间。只保存两个下标通常是 O(1)。递归调用会保留当前参数、局部变量和返回位置，所以也占空间，不能因为没有手动创建数组就写 O(1)。

输出所有排列的结果本身需要大量空间。教材会分别说明辅助空间和输出空间，避免一个地方包含输出、另一个地方排除输出却使用相同结论。

## 数据结构与操作需求

| 结构 | 适合的需求 | 需要理解的代价 |
| --- | --- | --- |
| 数组 | 按下标访问 连续遍历 | 一般头部插删需要移动后续元素 |
| Map | 按键找到关联信息 | 需要额外存储 按平均常数查询模型分析 |
| Set | 判断是否出现过 | 无法单独表达出现次数或对应下标 |
| 栈 | 按后进先出顺序处理元素 | 只操作同一端 无法直接找中间最值 |
| 队列 | 按先进先出顺序处理元素 | JS 数组反复 shift 不应默认常数时间 |
| 链表 | 已知节点处改变连接 | 按位置找节点仍需要沿指针走 |
| 堆 | 持续取最小值或最大值 | 不能像有序数组一样直接按排名随机访问 |

以括号为例，看到右括号时，应该先匹配最近尚未匹配的左括号。这是后进先出的需求，所以选择栈。以一层一层访问树为例，要先处理更早发现的节点，所以选择队列。名称只是这些操作规则的简称。

JS 的 Map 和 Set 通常用平均 O(1) 操作模型分析算法；语言规范并没有保证所有引擎、所有输入下每次操作严格常数。该分析模型描述理论操作成本，不等同于具体运行时间保证。

## 操作示例与成本边界

顺序放入 A、B、C 后，栈下一次取出 C，队列下一次取出 A。两种结构的差异首先体现为访问顺序，并进一步影响算法的处理顺序。

链表已经知道前驱节点时，删除它的后继只需改变连接；如果题目给的是第 k 个位置，则先找到前驱可能花 O(k)。说“链表删除都是 O(1)”遗漏了查找成本。

排序会改变原始顺序。需要返回原下标时，应保存下标与数值的关联，或采用不破坏该关联的方法。排序后的下标不能直接充当原输入下标。

## 练习

数组 `[4, 1, 4]` 中判断 4 是否出现过可以保存 Set。若问 4 出现几次，需要保存数值到次数的 Map。若问第一次出现的位置，需要保存数值到首次下标的 Map。**输入没变，输出要求变了，需要保留的信息也变了。**

本节检查要求是分别说明三种输出需求对应的存储内容。后续运行语义见 [TypeScript 运行时与递归](/leetcode/00-intro/03-ts-runtime-and-recursion)。
