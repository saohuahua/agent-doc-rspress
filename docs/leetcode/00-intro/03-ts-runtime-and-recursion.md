# TypeScript 运行时与递归

TypeScript 能检查类型，但算法最终运行在 JavaScript 上。类型正确不代表引用关系、数值范围和操作成本正确。

## 数组与对象保存的是引用关系

令 a 是一个数组，b 直接赋值为 a，修改 b 也会影响 a，因为它们引用同一个对象。展开语法复制数组只复制第一层；二维数组里的每一行仍可能共享引用。

回溯中保存当前路径时要复制路径。否则结果里多项指向同一数组，后面撤销选择会一起改变之前的答案。二维状态表也不能用填充同一个数组对象的方式创建各行，应为每行创建独立数组。

节点相交判断的是对象身份。两个链表节点都存 5，不代表它们是同一个节点。代码里的引用相等对应图上的同一个方框，值相等只代表方框里的数字相同。

## 容器与常见运行成本

- `Map.get` 返回的 0 可能是合法下标，不能用真假判断代替存在性判断；使用 `has` 或与 `undefined` 比较。
- 数字排序显式传入 `(a, b) => a - b`，默认排序按字符串顺序，10 可能排在 2 前面。
- `sort`、`reverse` 和 `splice` 修改原数组，`slice` 创建浅拷贝，复制本身需要时间和空间。
- 数组实现队列时用头下标推进，避免反复 `shift`。如果长期运行且需要回收头部空间，可以使用环形队列或适当压缩；一次性遍历也应计入保留的数组空间。

操作成本分析应明确是否发生复制、元素移动或调用方数据修改。这些行为既影响复杂度，也影响输入是否保持不变。

## 数值表示与字符单位

`number` 使用双精度浮点数。整数超过 `Number.MAX_SAFE_INTEGER` 后不能保证精确；需要更大精确整数时考虑 `bigint`，但它不能直接与 `number` 混算，也不一定符合题目接口。

普通位运算通常把 number 转成 32 位整数。异或方法是否合适要结合题目取值范围，不能把适用于 32 位整数的技巧随意推广到任意大数。

字符串按下标访问得到 UTF-16 码元，不一定是用户看见的一个完整字符。部分题目限制小写英文字母，可以安全按该范围处理；一般 Unicode 文本需要重新定义字符单位。`for...of` 遍历码点也不等于完整字素簇。

## 递归定义与调用栈

树的高度可由左右子树高度的较大值加一得到。递归实现将同一计算定义应用于规模更小的子树，当前调用等待子调用返回，再合并结果。

函数的语义约定为：给定一个节点，返回以它为根的子树高度。空节点高度为 0；非空节点的高度为左右子树高度的较大值加一。该约定同时定义了输入、返回值和递归终止条件。

| 当前调用 | 接下来等待什么 | 返回什么 |
| --- | --- | --- |
| 根节点 | 左右子树高度 | 两者最大值加一 |
| 叶节点 | 两个空子树 | 1 |
| 空节点 | 不再调用 | 0 |

每次进入子调用，父调用仍保存自己的节点和执行位置。等子调用返回，父调用接着执行，所以最大同时等待的层数决定调用栈空间。树有 n 个节点但高度为 h，一次深度优先遍历的递归栈通常为 O(h)，最坏链状树会达到 O(n)。

递归正确需要两个条件：最小问题有直接答案；每次调用都更接近最小问题。遗漏终止条件会无限深入，子问题不缩小也一样。JavaScript 引擎调用栈深度有限，特别深的输入可以改用显式栈，不能宣称递归写法对任意规模都不会溢出。

## 回溯中的共享状态恢复

设当前路径为空，先选 A，再选 B，得到一个候选。接下来要尝试 A 后面选 C，就必须先撤销 B，而不能保留 B 再接 C。撤销把共享路径恢复到父层开始尝试其他选择时的状态。

普通树遍历不一定需要撤销，因为每层只使用自己的局部变量。回溯需要撤销的原因是复用了可变的共享状态，不是因为只要递归就必须写撤销。
