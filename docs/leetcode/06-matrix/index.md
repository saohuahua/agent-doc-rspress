# 矩阵基础

## 二维坐标与存储结构

矩阵可以理解为行数组组成的数组，matrix[row][col] 先选行，再选列。若有 m 行 n 列，行下标范围零到 m - 1，列下标范围零到 n - 1。行数与列数不能因为测试用了方阵就混用。

阅读[入门基础](/leetcode/00-intro/)理解数组与引用。创建二维数组时，不能用一个内层数组填充所有行，否则各行共享引用，修改一格可能改变多行。需要为每一行独立创建数组。

## 坐标映射与几何变换

转置把 (r,c) 变成 (c,r)，顺时针旋转把 (r,c) 变成 (c,n - 1 - r)。画二乘二或三乘三追踪某一个格子，可以验证公式方向。用位置零和最大位置检查映射，可以检查边界是否越界以及方向是否正确。

方阵转置可原地交换对角线两侧元素，只交换一侧，避免换两遍。长方形转置后的尺寸改变，不能把方阵操作未经修改套过去。本章旋转图像的接口明确要求方阵。

## 原始状态与更新结果

矩阵置零要求根据原来为零的格子确定影响范围。若扫描到零立即清行列，新制造的零就可能成为错误依据。这类题先记录标记再统一修改，保证判断与执行分阶段。

用首行首列当标记可以省空间，但它们既是记录区又是原始数据。必须单独保存边界原有状态，并在内部处理完成前保持标记含义不被破坏。借用输入做存储时，最重要的是说明每一阶段哪些位置还表示原数据、哪些已表示标记。

## 剩余区域可以压缩成边界

螺旋遍历如果为每格保存 visited，会用额外矩阵。外圈走完后，剩余区域仍是矩形，因此四个边界已经充分。闭区间的 top、bottom、left、right 都包含端点，读完一边就把边界向内移。

一圈途中区域可能退化成一行或一列，所以不能只在外层开始检查有效性。角落也容易重复：读完上边后先增加 top，再读右边，才能排除刚读过的右上角。每个循环边界要对应清楚的尚未读取区域。

## 有序性与候选区域排除

行列均有序的矩阵，在右上角比较目标有特别价值：当前值过大，整列下面更大；当前值过小，整行左边更小。一次判断可删掉整条边，剩余区域依旧保持行列有序。

若只有行有序而列无序，就不能这样删列。若还保证下一行最小值大于上一行最大值，才可按行展开视作一维有序序列。相似题名不能代替这些条件检查。

## 复杂度与边界验证

读取整张矩阵至少 O(mn)，螺旋和旋转达到这个量级已合理；搜索则因排除整行整列可降到 O(m + n)。辅助空间与输出空间要分开：螺旋返回 mn 个数，输出本身不可能常数空间，但四个边界只占常数辅助空间。

每次至少手推方阵、单行、单列、长方形四类；旋转题只要求方阵，则使用一乘一、二乘二与奇数中心格。测试的形状由接口约束决定，不对不支持的矩阵形状伪造保证。
