# 0073 矩阵置零

阅读前提：[本章基础](/leetcode/06-matrix/)。[官方题目](https://leetcode.cn/problems/set-matrix-zeroes/)。

## 题目

:::info 题面

**难度**：中等

如果原矩阵某格为零，把它所在整行和整列都变成零。必须原地修改，不能让新产生的零继续触发连锁扩散。矩阵至少一行一列，数值可以为负，只有精确的零才是触发条件。

例如三行三列中只有中心为零，最终十字形一行一列清零，四角仍保留原值。这里“原矩阵”三个字决定了必须区分原始事实与修改后结果。

:::

### 官方示例

> **示例 1**
>
> 输入：matrix = [[1,1,1],[1,0,1],[1,1,1]]
> 输出：[[1,0,1],[0,0,0],[1,0,1]]

> **示例 2**
>
> 输入：matrix = [[0,1,2,0],[3,4,5,2],[1,3,1,5]]
> 输出：[[0,0,0,0],[0,4,5,0],[0,3,1,0]]

### 约束

- m == matrix.length
- n == matrix[0].length
- 1 <= m, n <= 200
- -2^31 <= matrix[i][j] <= 2^31 - 1

### 进阶要求

尝试把从 O(mn) 到 O(m + n) 的记录空间进一步降为常数空间。

## 前期思路

### 朴素方法与复杂度

朴素方法先记录哪些行和列包含原始零，再根据记录统一修改。对应代码可使用两个布尔数组，时间 O(mn)，额外空间 O(m + n)。这个方法已经清晰正确，进一步目标是复用矩阵本身保存标记，减少辅助空间。

不能一看到零就立即清空整行整列。比如 [[1,0],[1,1]]，先清第一行会制造位置 [0,0] 的零，若后续把它当原始零，就错误清掉第一列的底部值。阶段分离用于避免新写入的零污染后续判断依据。

### 从两张记录表到首行首列

每行只需一个标记，可以借该行第一格；每列只需一个标记，可以借该列第一格。内部出现零时，把相应首列格和首行格置零。然后只看这些标记清内部。

但首行首列本身也可能原来含零，且左上角同时属于二者，无法用一个格子表示两个独立事实。因此先用两个布尔变量分别记住“原首行是否有零”“原首列是否有零”。扫描范围与含义要说清，不能等标记写入后再检查，那时记录已被其他零污染。

### 算法推导与正确性

先单独扫描首行、首列保存原始事实。再扫描内部，遇原始零写入对应边界标记。标记期间不改变任何内部非零格，因此后面读取内部仍能准确识别原始零。

接着再次扫描内部，只要对应行标记或列标记为零，就把该格置零。最后根据两个布尔变量处理首行首列。边界最后处理，是因为它们仍承担标记存储职责，提前整行清零会让全部列看起来都该清空。

某内部格最终为零，当且仅当它所在行或列有原始零：首行首列原有零本身可作为对应标记，内部零也会写标记。因此不漏清，不多清。最后按原始零分布处理首行与首列，全部位置正确。

### 变式分析与错误反例

- 如果只有一个布尔值记录首行首列状态，[[1,0],[1,1]] 就无法区分应该清首行还是首列。若在内部置零前先把首行整体清零，所有列标记都被污染，会多清。
- 如果不允许修改输入，返回新矩阵时采用行列集合更直观，无需为了常数辅助空间借用原数据。类似“根据原状态批量更新”的题，先记录依据再统一执行是一种可迁移的方法，具体是否能借用边界则取决于数据结构。

## 执行过程示例

矩阵 [[1,1,1],[1,0,1],[1,1,1]]。

| 阶段 | 保存或改动 | 依据 |
| --- | --- | --- |
| 检查边界 | 两个布尔值都是 false | 原首行首列没有零 |
| 扫描中心 | [1,0] 与 [0,1] 写零 | 中心零影响第 1 行第 1 列 |
| 清理内部 | [1,2] 与 [2,1] 清零 | 对应行或列标记为零 |
| 处理边界 | 不把首行首列整体清零 | 原始布尔值均为 false |

最终 [[1,0,1],[0,0,0],[1,0,1]]。边界上的两个标记零也正是它们最终应有的值。

## 解法复述与检查

- 为什么不能边发现边清空？
- 首行首列能保存什么？
- 为什么额外需要两个布尔值？

:::details 解法概述

先保存首行和首列原本是否包含零，再利用首列记录各行的置零标记，利用首行记录各列的置零标记。内部扫描只写边界标记，不改动其他内部元素，避免新增零污染判断。随后按标记清零内部，最后根据原始布尔状态处理首行和首列。

:::

## TypeScript 实现

```ts
export function setZeroes(matrix: number[][]): void {
  const rows = matrix.length
  const cols = matrix[0].length
  let firstRowZero = false
  let firstColZero = false
  for (let col = 0; col < cols; col++) if (matrix[0][col] === 0) firstRowZero = true
  for (let row = 0; row < rows; row++) if (matrix[row][0] === 0) firstColZero = true
  // 用首行首列记录内部原始零的影响范围
  for (let row = 1; row < rows; row++) {
    for (let col = 1; col < cols; col++) {
      if (matrix[row][col] === 0) {
        matrix[row][0] = 0
        matrix[0][col] = 0
      }
    }
  }
  for (let row = 1; row < rows; row++) {
    for (let col = 1; col < cols; col++) {
      if (matrix[row][0] === 0 || matrix[0][col] === 0) matrix[row][col] = 0
    }
  }
  // 标记使用结束后再处理首行首列自身
  if (firstRowZero) matrix[0].fill(0)
  if (firstColZero) for (let row = 0; row < rows; row++) matrix[row][0] = 0
}
```

## 复杂度与边界

- 两次内部扫描加两条边界扫描，时间 **O(mn)**，只用两个标记变量，额外空间 **O(1)**，无递归，直接修改输入。
- 单行或单列时内部循环不进入，由原始边界标记决定结果。
- 左上角为零时两个布尔值均为真，首行首列都清零，但内部仍只按真实列行影响处理。
