# 0001 两数之和

本题要求在数组中选择两个不同位置，使对应数值之和等于目标值。推导从枚举位置对开始，分析固定一个数之后的查询需求，再据此确定需要保存的信息。

> 阅读前提：先读[本章基础](/leetcode/01-hash/)，理解数值和下标的区别，以及查询表保存的键和值。[官方题目](https://leetcode.cn/problems/two-sum/)

## 题目

:::info 题面

**难度**：简单

给定整数数组 `nums` 和目标值 `target`，返回两个不同位置的下标，使这两个位置的数值之和等于目标值。

输入 `nums = [3, 2, 4]`、`target = 6`，应返回 `[1, 2]`。这里的 `1` 和 `2` 是数组下标，对应数值是 `2` 和 `4`。返回 `[2, 4]` 表示数值，不符合返回下标的要求。

同一个位置不能用两次，但不同位置可以保存相同的数。例如 `[3, 3]` 的两个 `3` 能相加得到 `6`。题目保证恰好有一组答案，两个下标的返回顺序不限。输入没有承诺已经排序，数字可以为负数，也可以为零。

任务的关键约束是：**找两个不同下标，不是找两个不同数值。** 这个区别会直接决定之后的记录顺序。

:::

### 官方示例

> **示例 1**
>
> 输入：nums = [2,7,11,15], target = 9
> 输出：[0,1]

> **示例 2**
>
> 输入：nums = [3,2,4], target = 6
> 输出：[1,2]

> **示例 3**
>
> 输入：nums = [3,3], target = 6
> 输出：[0,1]

### 约束

- 2 <= nums.length <= 10^4
- -10^9 <= nums[i] <= 10^9
- -10^9 <= target <= 10^9
- 只会存在一个有效答案

### 进阶要求

尝试把枚举两数的 O(n²) 时间降到更低。

## 前期思路

### 朴素方法与复杂度

以 `[3, 2, 4]` 为例。先固定第一个数 `3`，分别和后面的 `2`、`4` 相加，都不等于 `6`。再固定第二个数 `2`，和后面的 `4` 相加，找到答案。

这个过程已经是一种正确算法：外层固定一个位置 `i`，内层从 `i + 1` 开始尝试另一个位置 `j`。不从 `0` 开始，是为了避免重复检查同一对位置；不从 `i` 开始，是为了避免拿同一个数两次。

长度为 `n` 时，最坏要检查 `(n - 1) + (n - 2) + ... + 1` 对，即 `n(n - 1) / 2` 对。数组扩大十倍，配对次数大约变成一百倍，所以时间为 O(n²)。只需要几个下标，额外空间为 O(1)。该方法可作为后续优化的正确性基线。

### 优化依据：将配对转换为确定值查询

固定 `3` 后，另一个数的取值已经确定。等式 `3 + 另一个数 = 6` 表明，另一个数只能是 `3`。固定 `2` 后，需要的数只能是 `4`。

因此优化目标是：**固定当前数字后，快速查询补数对应的位置。** 原内层循环的作用正是完成这一查询。

若预先记录全部数值的位置，查询时还需要排除当前位置。另一种方法只保存已处理位置的数值与下标：处理当前位置时先查询历史表，表中不含当前位置记录，因此命中的补数必定来自另一个位置。

仅保存数值是否出现还不充分。答案要求下标，所以记录必须同时保留位置。因此记录采用“数值 → 下标”的映射，用 TypeScript 的 `Map<number, number>` 表达。该查询需求适合哈希表：按确定数值检索关联下标，替代重复的线性扫描。

### 算法推导与状态约定

从左到右遍历，每次处理下标 `index`。

1. 计算所需补数 `needed = target - nums[index]`。
2. 查看历史表中有没有 `needed`。如果有，返回它的历史下标和当前下标。
3. 如果没有，将当前“数值 → 下标”记录进去，供后面的数字使用。

在每次查询开始时，表中保存的全是**当前位置之前出现过的数值及其某一个下标**。这句话叫状态约定，也可以叫不变量：它在每轮开始时都成立。最初没有经过任何数字，空表符合约定；本轮结束才加入当前数字，下一轮开始时约定仍成立。

完整性可由任意一组答案说明。设正确答案的两个位置是 `i` 和 `j`，并且 `i < j`。处理 `j` 时，位置 `i` 的数已经加入历史。即使相同数值后来覆盖了它，留下的也是一个早于 `j`、数值相同的合法位置。因此所需补数一定能查到。如果提前返回，则返回的一对已经满足和为目标且位置不同，同样正确。

这里不需要记住每个数的所有位置，因为题目只要一组答案。若要求所有配对，信息需求就变了，不能原样照搬。

### 变式分析与错误反例

- 如果只问“是否存在一对”，可以只记录数值是否出现，不需要下标，因此 `Set` 就够了。如果要求“返回所有下标配对”，`[1, 1, 1]`、目标 `2` 有三组，数值映射到单一下标会丢失历史，必须保存这个值的全部历史下标，并接受输出本身可能达到 O(n²)。
- 如果给的是已排序数组且只要求数值，可以考虑从两端逐步排除候选。但本题没有排序前提，不能看到“两数”就直接左右移动。比如 `[3, 2, 4]` 乱序时，大小比较不提供可靠的排除依据。先排序也必须一起保留原下标，并付出排序成本。
- 暴力枚举、先建完整映射和边遍历边查询三种路径也可对照[力扣官方题解](https://leetcode.cn/problems/two-sum/solutions/434597/liang-shu-zhi-he-by-leetcode-solution/)阅读。本篇选择先查询历史再记录，是为了让“不能重复使用同一位置”直接由状态约定保证。

## 执行过程示例：查询与记录顺序

输入 `[3, 2, 4]`，目标 `6`。表中的 `3 → 0` 表示数值 `3` 出现在下标 `0`。

| 当前下标 | 当前数 | 需要的数 | 查询前历史 | 决策与原因 | 本轮结束 |
| --- | --- | --- | --- | --- | --- |
| 0 | 3 | 3 | 空 | 历史没有 3 同一下标不能重复使用 | 记入 3 → 0 |
| 1 | 2 | 4 | 3 → 0 | 历史没有 4 留下 2 等后面的数字寻找 | 增加 2 → 1 |
| 2 | 4 | 2 | 3 → 0 和 2 → 1 | 找到下标 1 的 2 两个位置不同 | 返回 [1, 2] |

再看 `[3, 3]`、目标 `6`：第一轮没查到 `3`，于是记录 `3 → 0`；第二轮查到 `3 → 0`，返回 `[0, 1]`。**相同数值可以配对，但必须来自不同下标。**

错误做法是先把当前数放进表，再查询。仍用 `[3, 2, 4]`，第一轮就会查到刚写入的当前位置记录 `3 → 0`，错误返回 `[0, 0]`。这会破坏历史表仅包含已处理位置的状态约定。

## 解法复述与检查

独立于实现，需要能够说明以下问题：

- 最直接怎么做？
- 固定当前数以后究竟在找什么？
- 为什么表里保存下标？
- 为什么查找发生在记录之前？

:::details 解法概述

朴素方法枚举所有不同下标对，重复工作是固定一个数后再次扫描补数。由两数之和等于目标，可得补数等于目标减当前数，因此使用数值到历史下标的映射替代内层扫描。每轮先查询补数，命中则返回历史下标与当前下标；未命中才记录当前数。先查后记排除同一下标重复使用，任意合法配对都会在其较右下标处被发现。

:::

## TypeScript 实现

```ts
// 查找两个不同位置使对应数值之和等于目标
export function twoSum(nums: number[], target: number): number[] {
  // 记录已经经过的数值及其位置
  const seen = new Map<number, number>()
  for (let index = 0; index < nums.length; index++) {
    const value = nums[index]
    const needed = target - value
    // 先查询历史保证两个位置不同
    const previousIndex = seen.get(needed) // [!code highlight]
    // 下标零也是有效答案不能按真假判断
    if (previousIndex !== undefined) return [previousIndex, index]
    // 同值覆盖旧位置仍能保留一个可用搭档
    seen.set(value, index) // [!code highlight]
  }
  // 题目保证有解此分支服务于本地调用
  return []
}
```

本地使用命名导出便于测试，提交力扣时移除 `export` 即可。这里不使用 `if (previousIndex)`，因为下标 `0` 在 JavaScript 中是假值，会错过 `[2, 7]` 这一类答案。查不到时 `Map.get` 返回 `undefined`，应判断这个明确的缺失状态。

## 复杂度与边界

- 在算法题通常采用的哈希表平均常数时间假设下，每个位置最多一次查询和一次写入，时间为 **O(n)**，额外空间为 **O(n)**。
- ECMAScript 并不承诺所有具体引擎的 `Map` 操作最坏都是 **O(1)**，这里使用的是常见算法分析模型。
- 返回两个下标占 **O(1)** 输出空间，无递归栈。
- 不修改输入，不排序，也不会丢失原下标。
- 负数和零不需要额外分支。
- 题目数字范围内的整数及其加减结果可以被 JavaScript `number` 精确表示。
- 输入保证至少两个数且有唯一解，末尾返回空数组只为本地无解调用提供明确结果，不代表题目允许无解。
