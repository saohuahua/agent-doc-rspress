# 0001 两数之和

> 在数组中找两个不同位置，使对应数值之和等于目标值，返回这两个位置的下标。
>
> 阅读前提：[本章基础](/leetcode/01-hash/)（数值与下标的区别、查询表保存的键和值）· [官方题目](https://leetcode.cn/problems/two-sum/)
>
> 关联：[章节复习与迁移](/leetcode/01-hash/review) · [0560 和为 K 的子数组](/leetcode/04-substring/0560-subarray-sum-equals-k)，同一类把重复查找改成历史查询的问题

## 题目

:::info 题面

**难度**：简单

给定整数数组 `nums` 和目标值 `target`，返回两个不同位置的下标，使这两个位置的数值之和等于目标值。

输入 `nums = [3, 2, 4]`、`target = 6`，应返回 `[1, 2]`。这里的 `1` 和 `2` 是数组下标，对应数值是 `2` 和 `4`。返回 `[2, 4]` 表示数值，不符合返回下标的要求。

同一个位置不能用两次，但不同位置可以保存相同的数。例如 `[3, 3]` 的两个 `3` 能相加得到 `6`。题目保证恰好有一组答案，两个下标的返回顺序不限。输入没有承诺已经排序，数字可以为负数，也可以为零。

- **关键约束**：找两个不同**下标**，不是找两个不同**数值**，这个区别决定之后的记录顺序。
- **核心考点**：把枚举组合改写成对确定值的查询，并确定记录里键与值各承载什么信息。

:::

### 官方示例

> **示例 1**
>
> 输入：nums = [2,7,11,15], target = 9
> 输出：[0,1]

> **示例 2**
>
> 输入：nums = [3,2,4], target = 6
> 输出：[1,2]

> **示例 3**
>
> 输入：nums = [3,3], target = 6
> 输出：[0,1]

### 约束

- 2 <= nums.length <= 10^4
- -10^9 <= nums[i] <= 10^9
- -10^9 <= target <= 10^9
- 只会存在一个有效答案

### 进阶要求

尝试把枚举两数的 O(n²) 时间降到更低。

## 分层提示

:::details 提示一 先观察什么

固定一个数后，另一个数由等式唯一确定。内层循环做的不是组合计算，而是在查找一个已经算出来的值。

:::

:::details 提示二 需要维护什么信息

要按数值快速找到它之前出现的位置。只记“出现过没有”不够，因为输出要求的是下标。

:::

:::details 提示三 如何组织步骤

从左到右遍历，每轮先查“目标减当前值”这个补数有没有被记录过，命中就返回；没命中才记录当前值。查询发生在记录之前，命中的位置必然与当前不同。

:::

## 前期思路

### 朴素方法与复杂度

- 以 `[3, 2, 4]`、目标 `6` 为例：先固定 `3`，与后面的 `2`、`4` 相加都不等于 `6`；再固定 `2`，与 `4` 相加得到答案。
- 这已经是正确算法：外层固定位置 `i`，内层从 `i + 1` 开始尝试位置 `j`。
    - 内层不从 `0` 开始，避免重复检查同一对位置；
    - 不从 `i` 开始，避免同一个位置被用两次。
- 代价：长度为 `n` 时最坏检查 `n(n - 1) / 2` 对，时间为 O(n²)，额外空间为 O(1)。
- 用途：作为后续优化的正确性基线，也能在小规模输入上对照验证优化版本。

### 优化依据：把配对改写成确定值查询

- 固定 `3` 后，`3 + 另一个数 = 6` 把另一个数唯一确定为 `3`；固定 `2` 后，需要的数只能是 `4`。
- 于是内层循环只剩一个任务：**找出这个已经确定的补数在哪里**。优化目标是让这次查找不再扫一遍数组。
- 输出要求下标，记录必须同时保留位置，**记录形态确定为“数值 → 某个历史下标”**，用 `Map<number, number>` 表达。
- 只保存已处理过的位置还省掉一步排除：查询时表里没有当前位置，命中的补数必定来自另一个位置。

### 算法推导与正确性

从左到右遍历，每轮处理下标 `index`：

1. 计算补数 `needed = target - nums[index]`。
2. 查历史表中有没有 `needed`：有，返回它的历史下标与当前下标。
3. 没有，把当前“数值 → 下标”记进去，供后面的数使用。

**为什么这样做是对的**

- **状态约定（不变量）**：每轮查询开始时，表里只有当前下标之前出现过的数值，以及它们各自的一个下标。空表满足这个约定，本轮结束才写入当前数值，下一轮开始时约定继续成立，因此**命中时两个位置必然不同**。
- **覆盖性**：设某组答案为位置 `i` 与 `j`，且 `i < j`。处理 `j` 时位置 `i` 的值已经入表；即使相同数值后来覆盖过它，留下的仍是早于 `j`、数值相同的合法位置，所以这组答案一定会在 `j` 处被查到。
- **提前返回合法**：返回的那一对和为目标且位置不同，不会产生错误答案。
- **信息量刚好够**：题目只要一组答案，所以不必保存每个数值的全部位置；要求输出全部配对时信息需求会变，见“举一反三”。

### 错误做法与反例

- **先写入再查询**：`[3, 2, 4]`、目标 `6` 时第一轮就会命中刚写入的 `3 → 0`，返回 `[0, 0]`，两个下标相同。修正方式是把查询放回写入之前。
- **用 `if (previousIndex)` 判断是否命中**：下标 `0` 在 JavaScript 中是假值，`[2, 7]`、目标 `9` 的正确答案 `[0, 1]` 会被漏掉。判断依据只能是 `undefined` 这个明确的缺失状态。
- **只记录数值是否出现过**（`Set`）：拿不到下标，无法满足输出要求。
- **先整体排序再处理**：原下标会被打乱，还要额外保存值到位置的映射，并付出排序成本。

## 执行过程示例：查询与记录顺序

输入 `[3, 2, 4]`、目标 `6`，表中的 `3 → 0` 表示数值 `3` 出现在下标 `0`。

| 当前下标 | 当前数 | 需要的数 | 查询前历史 | 决策与原因 | 本轮结束 |
| --- | --- | --- | --- | --- | --- |
| 0 | 3 | 3 | 空 | 历史没有 3 同一下标不能重复使用 | 记入 3 → 0 |
| 1 | 2 | 4 | 3 → 0 | 历史没有 4 留下 2 等后面的数字寻找 | 增加 2 → 1 |
| 2 | 4 | 2 | 3 → 0 和 2 → 1 | 找到下标 1 的 2 两个位置不同 | 返回 [1, 2] |

- **重复值也要看一遍**：`[3, 3]`、目标 `6` 时第一轮未命中，记入 `3 → 0`；第二轮命中，返回 `[0, 1]`。相同数值可以配对，但必须来自不同下标。
- **顺序反了会怎样**：把写入放在查询之前，第一轮就会返回 `[0, 0]`，即上一节的错误做法。

## 解法复述与检查

独立于实现，需要能够说明以下问题：

- 最直接怎么做？
- 固定当前数以后究竟在找什么？
- 为什么表里保存下标？
- 为什么查找发生在记录之前？

:::details 解法概述

朴素方法枚举所有不同下标对，重复工作是固定一个数后再次扫描补数。由两数之和等于目标，可得补数等于目标减当前数，因此使用数值到历史下标的映射替代内层扫描。每轮先查询补数，命中则返回历史下标与当前下标；未命中才记录当前数。先查后记排除同一下标重复使用，任意合法配对都会在其较右下标处被发现。

:::

## TypeScript 实现

```ts
// 查找两个不同位置使对应数值之和等于目标
export function twoSum(nums: number[], target: number): number[] {
  // 记录已经经过的数值及其位置
  const seen = new Map<number, number>()
  for (let index = 0; index < nums.length; index++) {
    const value = nums[index]
    const needed = target - value
    // 先查询历史保证两个位置不同
    const previousIndex = seen.get(needed) // [!code highlight]
    // 下标零也是有效答案不能按真假判断
    if (previousIndex !== undefined) return [previousIndex, index]
    // 同值覆盖旧位置仍能保留一个可用搭档
    seen.set(value, index) // [!code highlight]
  }
  // 题目保证有解此分支服务于本地调用
  return []
}
```

- 本地使用命名导出便于测试，提交力扣时移除 `export` 即可。
- 最关键的一处实现细节是命中判断写成 `previousIndex !== undefined`：`Map.get` 查不到时返回 `undefined`，而下标 `0` 是假值（见下方易错点）。

## 复杂度与边界

- 在算法题通常采用的哈希表平均常数时间假设下，每个位置最多一次查询和一次写入，时间为 **O(n)**，额外空间为 **O(n)**。
- ECMAScript 并不承诺所有具体引擎的 `Map` 操作最坏都是 **O(1)**，这里使用的是常见算法分析模型。
- 返回两个下标占 **O(1)** 输出空间，无递归栈。
- 不修改输入，不排序，也不会丢失原下标。
- 负数和零不需要额外分支。
- 题目数字范围内的整数及其加减结果可以被 JavaScript `number` 精确表示。
- 输入保证至少两个数且有唯一解，末尾返回空数组只为本地无解调用提供明确结果，不代表题目允许无解。

### 易错点

- **查询与写入的顺序**：先 `set` 再 `get` 会用当前位置匹配自己，`[3, 3]` 会返回 `[0, 0]`；正确顺序是先查后写。
- **命中判断**：`Map.get` 查不到时返回 `undefined`，但下标 `0` 在 JavaScript 中是假值，只能用 `previousIndex !== undefined` 判断。
- **记录内容**：答案要求下标，只保存数值或者只保存布尔标记都拿不到位置。
- **输入修改**：不要为了“查得快”先排序或改写输入，那会失去原下标，也不符合题目对输出的定义。
- **无解分支**：实现末尾的 `return []` 只服务于本地调用。题目保证有解，不能把空数组当作合法答案提交。

## 举一反三

### A 同类变式：输出对象换成数值组合

把要求改成：返回所有**不同的数值组合**，同一组数值只输出一次。输入 `[1, 1, 1]`、`target = 2` 时只算一组 `(1, 1)`。问题：记录里还需要保存每个数值的全部历史下标吗，为什么？

:::details 参考思路

- **不需要**：输出按数值去重，每个数值保留“出现过”加上一个历史下标就够。
- **过程**：处理 `[1, 1, 1]` 时，第二个和第三个 `1` 都会命中补数 `1`，但产出的都是同一组 `(1, 1)`，在输出层面用集合去重即可。
- **记录内容随输出要求变化**：

| 输出要求 | 记录里必须保存 | 记录形态 |
| --- | --- | --- |
| 是否存在一对 | 数值出现过没有 | 集合 |
| 一组下标（本题） | 一个历史下标 | 值 → 下标 |
| 所有下标配对 | 每个数值的全部历史下标 | 值 → 下标数组 |
| 所有不同的数值组合 | 一个历史下标即可 | 值 → 下标 |

- **结论**：算法骨架几乎不变，变的只是表里存什么。要求“所有下标配对”时答案是 `[0, 1]`、`[0, 2]`、`[1, 2]` 三组，单一下标会覆盖早先的历史，输出规模本身可以达到 O(n²)，完整分析见[章节复习与迁移](/leetcode/01-hash/review)的练习二。

:::

### B 对比练习：什么时候该换成双指针

如果输入**已经按升序排好**，而且只要求返回两个数值，应该用哪种方法？本题（乱序、要求下标）为什么不能照搬？

:::details 参考思路

- **有序且只要数值时用双指针**：`left` 指向最小端，`right` 指向最大端；和偏小就右移 `left`，和偏大就左移 `right`，每一步都能排除一个候选。
- **排除依据来自有序性**：和偏小说明 `left` 与任何更靠左的右端只会更小，因此可以安全地丢掉一个候选。

| 对比点 | 哈希表（本题） | 双指针（已排序且只要数值） |
| --- | --- | --- |
| 依赖前提 | 只需按值精确匹配 | 输入必须有序 |
| 每步执行 | 查 `target - 当前值` | 比较两端之和后移动一端 |
| 时间复杂度 | 平均 O(n) | O(n) |
| 额外空间 | O(n) | O(1) |
| 保留原下标 | 天然保留 | 排序后丢失 |

- **本题不能照搬**：没有排序前提，`[3, 2, 4]` 这样的乱序输入里大小比较不提供可靠的排除依据。
- **先排序也不划算**：值与原下标的对应关系被打乱，要么额外保存位置映射，要么在重复值上处理歧义，还要付出 O(n log n) 的排序成本。
- **别混淆能力边界**：哈希表擅长精确匹配某个值，但不提供大小邻接关系，“查不大于 x 的最大值”这类需求要换结构，见[章节复习与迁移](/leetcode/01-hash/review)的练习三。

:::
