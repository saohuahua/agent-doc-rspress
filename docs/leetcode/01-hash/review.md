# 哈希章节复习与迁移

复习要求：不依赖参考答案，说明查询目标、键的含义和值的含义，并解释三者之间的关系。

## 练习一 只判断是否存在重复

给 `[7, 2, 7]`，只返回有没有重复，不需要位置或次数。最直接怎么做？需要保存哪些信息？

:::details 提示

读到第二个 7 时 只需要知道过去见过没有

:::

:::details 解析

直接方法让每个元素和后面元素比较，最坏 O(n²)。重复查询的内容是某个值是否已经出现，可以维护集合。从左到右先检查成员身份，出现过就返回 true，否则加入集合。遍历结束返回 false。无需关联信息，所以 Set 足够。时间在常用哈希模型下为 O(n)，额外空间 O(n)。

:::

## 练习二 两数之和改为返回所有位置配对

输入 `[1, 1, 1]`，目标 `2`，要求列出全部不同下标配对。继续让每个数只映射到一个下标，会丢什么？

:::details 提示

处理最后一个 1 时 前面的两个位置都能成为补数

:::

:::details 解析

答案是 `[0, 1]`、`[0, 2]`、`[1, 2]`。单一下标会覆盖早先记录，需要把值改为历史下标列表。每轮查到所需数的所有历史位置后逐个输出，再加入当前下标。由于只与历史配对，每组只输出一次。设输出数量为 k，则时间 O(n + k)，辅助存储 O(n)，输出空间 O(k)。k 本身可能是 O(n²)，不能承诺列出所有结果仍只用 O(n) 时间。

:::

## 练习三 能否直接找不大于目标的最大值

已有一百万个数字存入普通 Map，现在要频繁查询“不超过 x 的最大数字”。只用一次 `get(x)` 能解决吗？

:::details 提示

不存在精确的 x 时 查表结果不包含距离它最近的较小键

:::

:::details 解析

不能。哈希查询擅长精确身份匹配，不提供大小邻接关系。遍历所有键可以找出答案，但每次仍需 O(n)。如果数据静态且查询多，可以排序后使用二分查找，预处理 O(n log n)，每次 O(log n)。如果数据频繁变化，需要重新分析插入和查询的平衡，不能简单把静态排序方案当成所有场景的答案。

:::

- 能否解释先查询再记录与先记录再查询的区别
