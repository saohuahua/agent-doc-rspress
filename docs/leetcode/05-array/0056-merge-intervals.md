# 0056 合并区间

阅读前提：[本章基础](/leetcode/05-array/)。[官方题目](https://leetcode.cn/problems/merge-intervals/)。

## 题目

:::info 题面

**难度**：中等

输入若干闭区间 [start,end]，把所有重叠部分合并，返回互不重叠的区间。闭区间包含端点，所以 [1,4] 与 [4,5] 可以合成 [1,5]。目标是表达同一批被覆盖的位置，不是把区间数量固定减少到一。

:::

### 官方示例

> **示例 1**
>
> 输入：intervals = [[1,3],[2,6],[8,10],[15,18]]
> 输出：[[1,6],[8,10],[15,18]]

> **示例 2**
>
> 输入：intervals = [[1,4],[4,5]]
> 输出：[[1,5]]

> **示例 3**
>
> 输入：intervals = [[4,7],[1,4]]
> 输出：[[1,7]]

### 约束

- 1 <= intervals.length <= 10^4
- intervals[i].length == 2
- 0 <= starti <= endi <= 10^4

## 前期思路

### 朴素方法与复杂度

可以拿一个区间逐个和其他区间比较，找到重叠就合并，再检查合并后的结果是否与更多区间重叠。这样既可能重复比较，还容易忘记合并后产生的新连接。例如 [1,2]、[4,5]、[2,4] 会通过第三段连成一段。

一种反复两两比较直到没有变化的方案甚至需要多轮。优化方向是使可能重叠的区间在处理顺序上相邻，使每个新区间只需比较当前合并段。

### 优化依据：按左端排序

把区间按起点从小到大排。现在读到 [left,right]，所有未来区间的起点都不会更小。如果 left 已经大于当前合并段的右端，这个合并段就彻底结束了，后面的区间不可能再回头与它连接。

反之，left 不大于当前右端，则至少在某点重叠，应扩展当前段。新右端不是直接采用 right，而是原右端与 right 的较大值。因为新段可能完全被包含，例如 [1,10] 后面是 [2,3]，覆盖不能缩回到 3。

按左端排序把“与任意旧区间比较”变成“只和最后一段比较”。较早完成的段已经与当前段之间有空隙，不会被更靠右的新起点重新碰到。

### 算法推导与正确性

先复制并排序，结果数组起初为空。读到新区间，若结果为空或者它起点超过最后结果的终点，就新开一段；否则更新最后结果的终点为较大值。

处理到任何时刻，结果覆盖范围恰好等于已处理区间的并集，并且内部各段互不重叠。新区间有重叠时扩展最后一段，覆盖不多不少；不重叠时新增独立一段，同样保持这个事实。所有输入处理完，得到的就是完整覆盖的合并表达。

这里排序依赖数字比较，TS 必须提供比较器。实现同时复制每个内层区间，避免仅复制外层数组却在扩展右端时修改调用者的内层数组。

### 变式分析与错误反例

- 不排序就只比较最后一段，在 [4,5]、[1,2]、[2,4] 中会破坏前述“只向右扩展”的依据。用大于等于判断新段，则会把 [1,4] 和 [4,5] 错误拆开。
- 若区间改成左闭右开，两个区间 [1,4) 和 [4,5) 没有交点。究竟仍要把无缝相接的覆盖合成一段，取决于题目是要求合并相交还是简化覆盖表达，必须先确认端点语义。比较条件必须与区间定义及合并目标一致。

## 执行过程示例

输入 [1,3]、[2,6]、[8,10]、[15,18]，本来已按左端排好。

| 当前段 | 最后结果 | 决策与原因 | 结果 |
| --- | --- | --- | --- |
| [1,3] | 无 | 首段直接加入 | [1,3] |
| [2,6] | [1,3] | 2 不大于 3 合并右端为 6 | [1,6] |
| [8,10] | [1,6] | 8 大于 6 有间隙 | [1,6] [8,10] |
| [15,18] | [8,10] | 15 大于 10 有间隙 | [1,6] [8,10] [15,18] |

再检查包含关系 [1,10]、[2,3]，第二步取最大右端仍为 10。这是与一般“往后更新”直觉不同的地方。

## 解法复述与检查

- 排序以后为什么只检查最后一段？
- 闭区间端点相等时怎么办？
- 为什么终点必须取最大？

:::details 解法概述

按区间起点排序，维护已合并的结果。若新区间起点超过最后结果的终点，则新增一段；否则将最后终点更新为两者终点的最大值。排序保证未来起点不会更靠左，因此早期已分离的区间不可能再与未来区间连接，扫描时只需比较最后一段。

:::

## TypeScript 实现

```ts
export function merge(intervals: number[][]): number[][] {
  // 复制区间以避免排序和扩展影响输入
  const sorted = intervals.map(interval => [...interval]).sort((a, b) => a[0] - b[0])
  const result: number[][] = []
  for (const interval of sorted) {
    const last = result[result.length - 1]
    if (last === undefined || interval[0] > last[1]) result.push(interval)
    // 起点排序只保证左边有序右边仍需取最大值
    else last[1] = Math.max(last[1], interval[1])
  }
  return result
}
```

## 复杂度与边界

- 排序 **O(n log n)**，单次扫描 **O(n)**，总 **O(n log n)**。
- 复制全部区间占 **O(n)** 辅助空间，结果最多 **O(n)**，排序内部空间依引擎实现计入。
- 无递归代码，输入及其内层数组不修改。
- 相同区间只保留合并的一段，单点闭区间合法，题目整数比较不存在精度问题。
