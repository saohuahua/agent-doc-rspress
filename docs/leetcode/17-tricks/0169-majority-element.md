# 0169 多数元素

严格多数的出现次数大于其他所有值的出现次数之和。删除一对不同值不会改变多数身份，因此可以利用逐对抵消减少需要保存的计数信息。

相关基础：[本章基础](/leetcode/17-tricks/)。[力扣原题](https://leetcode.cn/problems/majority-element/)。

## 题目

:::info 题面

**难度**：简单

输入非空数组，题目保证存在一个元素出现次数严格大于数组长度的一半，返回该元素。不是返回频率最高但未过半的值，也不是找中位数下标。保证存在是本解法直接返回候选的关键。

:::

### 官方示例

> **示例 1**
>
> 输入：nums = [3,2,3]
> 输出：3

> **示例 2**
>
> 输入：nums = [2,2,1,1,1,2,2]
> 输出：2

### 约束

- n == nums.length
- 1 <= n <= 5 * 10^4
- -10^9 <= nums[i] <= 10^9
- 输入保证数组中一定有一个多数元素。

### 进阶要求

尝试达到 O(n) 时间与 O(1) 额外空间。

## 前期思路

### 朴素方法与复杂度

用Map给每个值计数，遇到计数超过一半便返回，时间O(n)、空间O(n)。排序后中间项也一定是多数，但要排序。若想用常数空间，问题变成能否在遍历中安全消去不会改变多数结论的信息。

### 优化依据

不必知道所有少数值分别出现多少次。将不同值两两删除，如果这一对包含多数值，它和其他总数各减一，多数仍严格占优；如果不包含，多数占比更高。因此可以持续消去异值对，最后未消去的值应属于原多数。

### 算法推导

维护candidate和balance。balance表示当前尚未抵消的一批相同候选有多少个，不是candidate在原数组中的真实总次数。余额为零时，把新值选作候选。新值等于候选就加一，不等就减一，相当于配对删除一项候选与当前异值。

余额归零后可以更换候选，因为前面整批已经分成若干异值对，删掉它们不改变严格多数的身份。剩余后缀与未消去项中仍能保留多数优势，因此重新开始不会抛弃唯一可能胜出的值。

到末尾，由于原多数比所有其他值加起来多，不可能被完全抵消，留下的候选必是它。这个过程叫多数投票。若题目不保证存在，算法仍会产生候选，但候选只是可能值，必须额外计数验证，不能把“留下一个”当成过半证明。

### 变式分析与错误反例

- 若只保证有元素出现超过三分之一，可同时维护至多两个候选并做三种不同值抵消，最终仍要计数验证。这个变化不是简单把阈值改成三分之一，因为一个候选槽不足以保留两种可能答案。
- 错误反例：`[1,2,3]`会留下3，但3没有超过一半。若题目没有多数保证而直接返回候选，就把候选生成误当成结果验证。

## 执行过程示例

输入`[2,2,1,1,1,2,2]`。

| 当前值 | candidate | balance | 原因 |
| --- | --- | --- | --- |
| 2 | 2 | 1 | 空余额选候选 |
| 2 | 2 | 2 | 同值累计 |
| 1 | 2 | 1 | 配对抵消 |
| 1 | 2 | 0 | 该批抵消完 |
| 1 | 1 | 1 | 重新选候选 |
| 2 | 1 | 0 | 再抵消 |
| 2 | 2 | 1 | 多数最终留下 |

## 解法复述与检查

- balance为什么不是总次数？
- 为什么一对不同值可以删除？
- 没有多数保证时还差哪一步？

:::details 算法概述

将不同值成对抵消，多数值严格过半，所以删掉异值对后仍不会失去多数身份。遍历用候选与未抵消余额实现这个过程，同值加一，异值减一，归零就换候选。题目保证多数存在，因此最后留下的候选就是答案；否则还需第二遍计数。

:::

## TypeScript 实现

```ts
export function majorityElement(nums: number[]): number {
  let candidate = nums[0]
  let balance = 0
  for (const num of nums) {
    // 余额归零说明此前这一批已被不同值成对抵消
    if (balance === 0) candidate = num
    balance += num === candidate ? 1 : -1
  }
  return candidate
}
```

## 复杂度与边界

- 时间**O(n)**，辅助空间**O(1)**，不修改输入。
- 不使用位运算，因此不依赖32位截断。
- 非空与多数存在是题目约束，不能对空数组或无多数数据宣称同样结论。
