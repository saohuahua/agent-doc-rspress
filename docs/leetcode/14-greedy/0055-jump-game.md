# 0055 跳跃游戏

本题只判断终点是否可达，不要求恢复路径。推导的关键是证明可达位置是否构成连续区间，从而判断一个最远边界能否代替全部历史路线。

相关基础：[本章基础](/leetcode/14-greedy/)。[力扣原题](https://leetcode.cn/problems/jump-game/)。

## 题目

:::info 题面

**难度**：中等

输入非负整数数组，从下标0出发，每项表示从该位置最多能向右跳的步数。可以选择不超过该上限的步长，判断能否到达最后下标。只问是否可达，不要求最少次数或实际路径。

:::

### 官方示例

> **示例 1**
>
> 输入：nums = [2,3,1,1,4]
> 输出：true

> **示例 2**
>
> 输入：nums = [3,2,1,0,4]
> 输出：false

### 约束

- 1 <= nums.length <= 10^4
- 0 <= nums[i] <= 10^5

## 前期思路

### 朴素方法与复杂度

可以递归枚举每个位置允许的所有落点，直到到达终点或所有选择失败。同一位置可能被不同路线重复到达，继续展开的后续问题也重复。保存每个位置是否可达能减少重复，但还可以利用可达范围是连续区间这一额外结构。

### 优化依据

从可达位置i能够选择1到nums[i]的任何合法步长，因此如果能延伸到某个右端点，中间位置也都可达。无需逐条记录路径，只保存最远可达下标reach。关键前提是最多跳，而不是必须恰好跳。

### 算法推导

初始化reach为0，表示起点可达。从左向右检查位置i。如果i大于reach，说明前面所有可达位置都无法跨过这个缺口，后面再大的跳跃能力也不能使用，立即失败。否则i已被证明可达，可以把i加nums[i]作为新的候选远端，与reach取较大值。

归纳地说，处理前面位置后，从起点到reach之间形成连续可达区间。新可达位置给出的跳跃区间与原范围相交，合并后仍连续。每次只使用已经可达的位置更新，不会借用无法踏上的跳板。reach一旦达到或超过末尾，就能选择合适步长停在末尾，立即成功。

这里不是每次实际跳最远，而是保留全部可达位置共同形成的边界。即使最远落点本身是零，也可能由更靠前的位置继续扩展。

### 变式分析与错误反例

- 若需要最少跳数，单个reach不能说明用了几步，还需维护同一跳数层的结束边界，见本章下一题。若步长改成恰好等于nums[i]，中间不一定可达，这个连续覆盖证明失效。
- 错误反例：`[0,100]`不能用位置1的100扩展范围，因为根本到不了1。`[2,0,0]`则能够到终点，不能看到数组含零就直接失败。

## 执行过程示例

输入`[2,3,1,1,4]`。

| 位置 | 进入时reach | 能否使用 | 更新结果 |
| --- | --- | --- | --- |
| 0 | 0 | 起点可达 | reach变2 |
| 1 | 2 | 在覆盖区域内 | 1加3使reach变4 |

终点下标4已覆盖，直接返回true。无需实际确定从0跳到1还是2的最终路径。

## 解法复述与检查

- reach代表一次实际跳跃还是所有已知路径的覆盖？
- 为什么遇到i超过reach立即失败？
- 为什么允许超过终点也算成功？

:::details 算法概述

维护已经证明可达的最远边界。从左向右，只处理边界内的位置，用它的最远落点扩展边界。若下一个位置已经在边界外，就没有路径能越过缺口；若边界覆盖终点就成功。连续覆盖成立依赖每次可以选择上限内任意步长。

:::

## TypeScript 实现

```ts
export function canJump(nums: number[]): boolean {
  let reach = 0
  for (let i = 0; i < nums.length; i++) {
    // 不可达的跳板不能贡献它的跳跃长度
    if (i > reach) return false
    reach = Math.max(reach, i + nums[i])
    if (reach >= nums.length - 1) return true
  }
  return false
}
```

## 复杂度与边界

- 时间**O(n)**，辅助空间**O(1)**，不修改输入。
- 官方数组非空，单个0已经站在终点，返回true。
- 前方出现零并不必然失败，只要之前的覆盖能跨过它即可。

已可达位置能覆盖一段连续落点 而非只有最远一个点

:::

:::details 提示二 需要维护什么信息
