# 0121 买卖股票的最佳时机

一次交易需要同时确定买入日和卖出日。固定卖出日以后，利润只随此前买入价变化，因此可以把两端枚举转化为历史最小值查询。

相关基础：[本章基础](/leetcode/14-greedy/)。[力扣原题](https://leetcode.cn/problems/best-time-to-buy-and-sell-stock/)。

## 题目

:::info 题面

**难度**：简单

输入每天股价，只允许先买一次再在后面的某天卖一次，返回最大非负利润。可以不交易，因此全程下跌返回0。不能卖出后再买入，也不是累加所有上涨区间的利润。

:::

### 官方示例

> **示例 1**
>
> 输入：[7,1,5,3,6,4]
> 输出：5

> **示例 2**
>
> 输入：prices = [7,6,4,3,1]
> 输出：0

### 约束

- 1 <= prices.length <= 10^5
- 0 <= prices[i] <= 10^4

## 前期思路

### 朴素方法与复杂度

枚举买入日，再枚举其后的卖出日，计算差值并取最大。这覆盖全部合法交易，但需要O(n²)次比较。也可以固定卖出日，扫描其前面找最低价，仍是平方级，只是交换了枚举角度。

### 优化依据

卖出日从今天移动到明天时，过去日期几乎完全相同，没必要再次求一遍过去最低价。需要保存此前最低价和截至目前最优利润两项信息。前者帮助评价新卖出日，后者保留历史答案，二者职责不能合并。

### 算法推导

从第一天价格初始化最低价，利润为0。从第二天开始，把今天作为卖出日，用今日价格减去此前最低价，更新最优利润。然后把今天价格纳入最低价记录，为未来卖出日服务。先计算再更新，使时间先后在代码里清晰成立。

固定卖出日后保留最低买价不会损失最优性：当日卖出价相同，买入价越低，利润越大。任何别的历史买入日都不会更好，因此只留下最低价足够。循环检查了每个可能卖出日，整体最优的卖出日也会被检查；该日配合的最低历史价至少不差于其余买入选择。

不必保存具体买入日期，因为题目只问利润。若两天价格相同，保留哪一天的最低价不影响数值答案。初始化利润为零表示不交易，避免被负利润覆盖。

### 变式分析与错误反例

- 若要求交易日期，需要同时保存最低价下标，以及更新最佳利润时的买卖下标。若允许多次买卖，历史最低价方法会漏掉多段收益，必须重新分析新规则，不能仅多加一次循环。
- 错误反例：`[5,1]`若先找全局最高5与最低1再相减，会返回4，但最高价发生在最低价之前，无法合法获利。时间顺序是可行性约束，不是最后再检查的细节。

## 执行过程示例

价格`[7,1,5,3,6,4]`。

| 卖出日价格 | 此前最低 | 当日可得 | 历史最好 |
| --- | --- | --- | --- |
| 1 | 7 | -6 | 0 |
| 5 | 1 | 4 | 4 |
| 3 | 1 | 2 | 4 |
| 6 | 1 | 5 | 5 |
| 4 | 1 | 3 | 5 |

第一次处理1后最低价更新为1，后续评价不需重复扫描。

## 解法复述与检查

- 为什么只保存一个最低价？
- 它与历史最好利润有什么区别？
- 为什么先算今天卖出再记录今天买入？

:::details 算法概述

依次把每天当卖出日，卖出价固定时此前越低的买价越好，所以只保存历史最低价。用今天减最低价更新最大利润，再将今天纳入最低价，给后续日子使用。检查所有卖出日就覆盖最优交易，全程无利可图时保留零。

:::

## TypeScript 实现

```ts
export function maxProfit(prices: number[]): number {
  if (prices.length === 0) return 0
  let lowest = prices[0]
  let best = 0
  for (let day = 1; day < prices.length; day++) {
    // 先用此前价格评价卖出 保持买入早于卖出
    best = Math.max(best, prices[day] - lowest)
    lowest = Math.min(lowest, prices[day])
  }
  return best
}
```

## 复杂度与边界

- 时间**O(n)**，辅助空间**O(1)**，不修改输入。
- 只有一天时不能完成交易，返回0。
- 全等、全降也是0。
- 空输入返回0作为防御，但题目本身给非空数组。
