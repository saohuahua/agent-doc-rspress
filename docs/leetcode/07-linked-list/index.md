# 07 链表基础 对象引用与连接修改

数组支持按下标访问，链表则通过节点之间的引用访问后继。链表算法的核心是维护连接与可达性：修改某条边后，未处理节点仍须保留入口；输出语义也须区分节点值与节点对象身份。以下分别说明节点表示、操作成本和连接修改的边界。

## 节点身份与节点值

节点是对象，通常含 val 和 next。val 是数据，next 是后继节点的引用，末尾用 null 表示没有后继。两个节点都保存 7，不代表它们是同一个节点；两个变量指向同一个节点，则其中一个变量修改该节点，另一个也能观察到。相交与环检测比较对象身份，回文比较节点值，这个差异必须先从题目读出。

`let current = head` 不会复制链表，只是多了一个指向同一头节点的变量。`current = current.next` 只移动局部变量，不改变链表；`current.next = other` 才改变实际连接。前端开发中对象浅拷贝与嵌套引用也有类似问题，但链表更直接地把连接本身当成需要处理的数据。

## 访问方式与操作成本

单链表节点只知道自己的后继，没有索引表，也不知道前驱。从头访问第 k 个节点需经过 k 次左右的连接，时间 O(k)。即使已知尾节点，也无法沿 next 访问前驱。寻找某节点可能很慢，但一旦已知其前驱，跳过它只需一次 next 赋值，时间 O(1)。说“链表删除是常数时间”时，必须说明已经知道哪个前驱，不能忽略寻找成本。

数组在尾部追加通常方便，链表如果只保存头，尾部追加还需先走到尾；同时维护 tail 才能省掉扫描。操作复杂度取决于维护的引用和索引信息。

## 连接的插入与删除

原结构 A→B→C，要删除 B，让 A.next 指向 C。局部变量 B 可能仍指向旧节点，所谓删除是从当前链的可达路径中移除，不是立即销毁对象。在删除 B 后的 A→C 之间插入 X 时，先保存 C，再建立 A→X→C。次序错误可能让 C 失去最后入口。

反转 1→2→3 时，把 1.next 改成 null 之前，必须先保存原后继 2。若该后继只由原 next 引用，覆盖 next 就会丢失未处理部分的访问入口。因此每次改边前，需要确认原目标仍被其他局部引用或链表边保存。

## 哨兵节点与边界统一

删除中间节点有前驱，删除头没有前驱，容易多写一套分支。在 head 前增加 dummy，就能统一处理。最后返回 dummy.next，它可能是原头，也可能是新头或 null。dummy 的值没有业务意义，不应计入答案。该结构将删除头节点等特殊边界统一为普通的前驱连接修改。

双向链表还记录 previous，已知节点时就能同时找到两侧邻居。LRU 用它实现任意节点常数时间摘除；但每次改边都要更新双向关系，不能只修一边。首尾哨兵让空链也拥有可用的边界邻居。

## 不同指针关系的定位依据

两个指针走不同速度可以定位中点，也可以在环内追赶；两个同速指针维持固定距离可以定位倒数节点。它们外观相似，证明却不同。中点依赖快指针走两倍距离；环检测依赖有限环内相对位置变化；倒数定位依赖固定间距直到末尾。因此指针数量本身不能说明正确性，必须给出速度或间距与目标位置之间的关系。

对于改边题，应维护已处理区域和未处理入口；对于查询题，应明确是否允许修改输入。有些算法会短暂修改再恢复，回文判断就是例子。恢复要覆盖失败分支，不能发现不匹配就提前返回。

## TypeScript 表示与验证

本项目共用 `ListNode` 和 `RandomNode`，类型中的 `| null` 显式表示空链或链尾。非空断言只表达已由循环条件或题目约束保证的事实，不能替代检查。比如快指针走两步前必须确认它和它的 next 存在。

手推时给节点标注身份 a、b、c，旁边另写 val。测试除检查值，还应检查引用是否保留、next 是否恢复、有没有意外环。深拷贝则要确认所有新节点都不是旧对象，且所有新边都位于副本中。单看打印出来的值可能完全发现不了浅拷贝问题。
