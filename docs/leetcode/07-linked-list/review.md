# 链表复习与迁移

思路检查包括输出值或引用的语义、允许修改的连接、改边前保留的入口，以及终止时的答案位置。连接图与算法复述用于验证推导，TypeScript 实现另行验证边界和赋值顺序。

## 练习一 只有待删节点 没有头指针

给定非尾节点 B，结构是 A→B→C→D，只能访问 B，如何让链上的值序列表现得像删掉 B？为什么尾节点不适用？

:::details 提示与解析

没有前驱就不能改 A.next。可以将 C.val 复制到 B.val，再令 B.next=C.next。数值序列看起来删除了原 B 值，但实际被移出的对象是 C。如果题目要求删除特定对象身份，这个方法不满足要求；尾节点没有后继可复制，也无法通知未知前驱断边。这里必须区分值序列效果与对象身份语义。

:::

## 练习二 禁止暂时修改输入的回文判断

调用期间其他逻辑可能读取同一条链，要求任何时刻都不改 next。还能使用反转后恢复吗？

:::details 提示与解析

不能。返回时恢复不等于全过程只读。可把值保存到数组，再从两端比较，时间 O(n)，辅助空间 O(n)。也可用栈保存前半，但仍需线性空间。选择方案时必须把修改权限当作输入约束，而不是只追求空间复杂度更小。

:::

## 练习三 环入口和相遇点

画 a→b→c→d→b，快慢每次分别两步和一步。首次相遇在哪？若需要环长度，接下来怎样做？

:::details 提示与解析

三轮后在 d 相遇，入口是 b。定位入口时，一个回到 a，另一个在 d，同速一步后到 b。计算环长则从 d 再沿 next 前进，数到再次回到 d 为止，得到 3；不必先知道入口。两种后续目标使用不同的信息，不能把相遇点直接当答案。

:::

## 练习四 合并的两条链共享尾部

两条有序链分别为 1→shared3 和 2→shared3，直接使用复用节点的普通合并会有什么风险？

:::details 提示与解析

共享节点可能被两边当作不同待处理节点重复接入，产生自环。若需求把共享节点只保留一次，可以在合并时检测两个当前引用相同并直接接一次余尾；若要求按两个输入序列重复保留共享值，就必须新建输出节点。需要先定义输出身份语义，不能用普通独立链前提替代需求决定。

:::
