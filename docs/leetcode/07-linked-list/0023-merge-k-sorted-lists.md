# 0023 合并 K 个升序链表

相关基础：[本章基础](/leetcode/07-linked-list/)。[官方题目](https://leetcode.cn/problems/merge-k-sorted-lists/)。

## 题目

:::info 题面

**难度**：困难

给出 k 条分别有序的链表，输出一条包含全部节点的升序链。数组里可能有空链，数组本身也可能为空。总节点数记为 N，链条数 k 和节点数 N 分别控制不同部分的计算成本。主解复用节点，因此假设输入链互不共享节点且无环，后续连接会被改变。先读 0021 的两路合并。

:::

### 官方示例

> **示例 1**
>
> 输入：lists = [[1,4,5],[1,3,4],[2,6]]
> 输出：[1,1,2,3,4,4,5,6]

> **示例 2**
>
> 输入：lists = []
> 输出：[]

> **示例 3**
>
> 输入：lists = [[]]
> 输出：[]

### 约束

- k == lists.length
- 0 <= k <= 10^4
- 0 <= lists[i].length <= 500
- -10^4 <= lists[i][j] <= 10^4
- lists[i] 按 升序 排列
- lists[i].length 的总和不超过 10^4

## 前期思路

### 朴素方法与复杂度

可以每次扫描 k 个当前头，选出最小值接入结果，产生 N 个输出时最坏需要 O(Nk) 次比较。另一个直观办法是不断把新链并入累计结果，但如果很多链长度相近，早先的节点会参与后面大量合并，也可达到 O(Nk)。瓶颈是有些节点被反复扫描太多轮。

### 优化依据

既然已经会合并两条，问题可以变成怎样安排合并顺序。让链条数量每轮减半：第一轮两两合并，第二轮再两两合并，直到只剩一条。这样一条原链最多经历 log k 层合并，不会从第一轮一直参与到第 k 轮。这个安排把已有的小工具组织成分治过程，无需同时管理 k 个头。

### 算法推导

combine(left,right) 的含义是合并 lists 这个闭区间内的全部链。区间只有一条时，直接返回它的头。否则取中点，把两半分别合成有序链，再用 merge 合并这两个结果。

正确性分两层：merge 每次选两个当前头的较小值，保证输出有序且不漏节点；combine 的两半覆盖整个区间而不重叠，因此把两个正确结果合起来，就是整个区间的正确结果。每次区间长度缩小，递归最终到单条链。

空链对 merge 没有影响，一边为空时直接接另一边。数组为空必须在递归前处理，否则不存在有效闭区间。主解没有改写 lists 数组元素，但节点重连意味着原来的多个头可能已经处于同一条合并链中，不应宣称输入完全不变。

### 变式分析与错误反例

- 错误反例：全部链都为空但 k 很大时，N=0，并不代表调用次数为零，因此精细分析应保留 O(k)。只按长度 N 表述可能掩盖管理成本。逐条合并在 k 条单节点链时累计比较可达平方。
- 若链持续动态到达，预先分治的静态数组不方便，可使用维护当前各链头的最小堆，每次取最小后放入该链后继。时间通常也是 O(Nlog k)，但额外保存 k 个候选。这是根据输入方式选择实现，不是只看最终大 O 就断言完全相同。

## 执行过程示例

三条链为 A=1→4，B=2→5，C=3→6。

| 合并范围 | 输入结果 | 返回结果 |
| --- | --- | --- |
| A 与 B | 1→4 和 2→5 | 1→2→4→5 |
| C 单条 | 3→6 | 直接返回 |
| 全部 | 1→2→4→5 和 3→6 | 1→2→3→4→5→6 |

最终一轮处理全部 N 个节点，但不是每条新链到来都重扫所有旧节点。均衡拆分保证递归高度随 k 的对数增长。

## 解法复述与检查

复述检查：

- 逐条并入累计结果为什么会反复扫描旧节点？
- 对半安排合并如何限制每个节点参与的层数？
- 全是空链时还有哪些成本？

:::details 算法概述

首先把合并很多条转成反复合并两条。为了避免累计结果被重复扫描太多次，将链条数组对半分，各自合成有序链，再合并两个结果。单条链直接返回，空数组直接返回空。每层所有节点合计最多处理一次，层数为 log k。

:::

## TypeScript 实现

本地保留导出及共用类型导入以便测试。提交时移除模块导入和导出，节点定义使用力扣模板；随机节点的类名按模板调整。

```ts
import { ListNode } from '../shared.js'

export function mergeKLists(lists: Array<ListNode | null>): ListNode | null {
  if (lists.length === 0) return null
  function merge(a: ListNode | null, b: ListNode | null): ListNode | null {
    const dummy = new ListNode()
    let tail = dummy
    while (a !== null && b !== null) {
      if (a.val <= b.val) {
        tail.next = a
        a = a.next
      } else {
        tail.next = b
        b = b.next
      }
      tail = tail.next
    }
    tail.next = a ?? b
    return dummy.next
  }
  function combine(left: number, right: number): ListNode | null {
    if (left === right) return lists[left]
    const middle = Math.floor((left + right) / 2)
    // 两边各自合并完成后再进行一次两路合并
    return merge(combine(left, middle), combine(middle + 1, right))
  }
  return combine(0, lists.length - 1)
}
```

## 复杂度与边界

- k≥2 时节点合并时间 **O(Nlog k)**，另有 **O(k)** 的区间递归管理成本，完整可写 **O(k+Nlog k)**；k=0 或 1 为常数入口开销。
- 辅助空间 **O(log k)** 来自递归栈，merge 本身 **O(1)**。
- 输出重用节点，不分配 N 个新节点，输入 next 会改变。
