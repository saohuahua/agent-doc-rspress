# 0230 二叉搜索树中第 K 小的元素

相关基础：[本章基础](/leetcode/08-binary-tree/)。[官方题目](https://leetcode.cn/problems/kth-smallest-element-in-a-bst/)。

## 题目

:::info 题面

**难度**：中等

给的是有效二叉搜索树，返回第 k 小的数值，k 从 1 开始且保证不超过节点总数。本题不是普通二叉树找第 k 小，也不要求返回节点对象。搜索树已有全局大小顺序，可以利用它避免先收集全部值再排序。先读 0094 理解中序访问，再把访问顺序与排名联系起来。

题面配图用节点和左右连线表示树；示例中作为树的数组按层序列出节点，`null` 表示对应的孩子不存在。数组表示的是连接结构，不要求按数值排序。

:::

### 官方示例

> **示例 1**
>
> 输入：root = [3,1,4,null,2], k = 1
> 输出：1

> **示例 2**
>
> 输入：root = [5,3,6,2,4,null,null,1], k = 3
> 输出：3

### 约束

- 树中的节点数为 n 。
- 1 <= k <= n <= 10^4
- 0 <= Node.val <= 10^4

### 进阶要求

考虑二叉搜索树经常增删节点且频繁查询第 k 小值时 怎样维护额外信息。

## 前期思路

### 朴素方法与复杂度

普通做法是遍历收集 n 个值，排序后取下标 k-1，时间 O(nlog n)，空间 O(n)。但这等于重新建立输入已经提供的顺序。手工观察一棵搜索树，最小值位于最左路径的末端；访问完某个根左侧全部节点，才轮到根本身，再轮到右侧较大的值。

### 优化依据

中序输出恰好递增，是因为左子树所有值小于根，右子树所有值大于根，左右内部递归也按同样顺序。于是第 k 次中序访问就是目标，无须保存完整输出数组，只需记住还差几个访问位置。栈保留返回路径，计数器保存排名进度，这两类状态职责不同。

### 算法推导

current 沿左边一直走并压栈，走到空后弹出最近祖先，此时正轮到它被中序访问。每弹出一个实际节点，k 减一，减到零立即返回其值。若未到目标，则转向该节点右子树，重复先左后根的过程。

不能在压栈时减 k，因为压栈表示暂存，还没有处理它的左子树。例如根 3 左有 1，压入 3 并不意味着它排名第一。也不能按节点深度或经过的边数计数，排名只由正式访问顺序决定。

合法输入保证第 k 次访问存在，所以一定会在循环中返回。末尾抛错服务于本地误用诊断，不是题目正常分支。提前返回只停止查询，不改树结构。

### 变式分析与错误反例

- 错误反例：根 3 左有 1，若压栈时就计数，k=1 会返回 3；如果只是找最左节点后不断走 right，也可能无法回到祖先，漏掉后续排名。
- 若树经常插入删除且要反复查询排名，可在节点维护子树大小，比较 k 与左子树大小来跳过整块，但更新时也要维护大小，平衡与否仍影响复杂度。若输入不是搜索树，中序没有排序保证，必须先排序或使用选择结构。

## 执行过程示例

根 3，左孩子 1，1 的右孩子 2，右孩子 4，求第 2 小。

| 操作 | 待返回栈 | 剩余 k | 说明 |
| --- | --- | --- | --- |
| 压 3 再压 1 | 3 1 | 2 | 尚未正式访问 |
| 弹 1 | 3 | 1 | 最小值为 1 |
| 展开 1 的右边 压 2 | 3 2 | 1 | 下一位来自这棵右树 |
| 弹 2 | 3 | 0 | 返回 2 不再处理 3 和 4 |

访问较小节点的右子树先于返回更高祖先，这是中序顺序的重要细节。

## 解法复述与检查

复述检查：

- 为什么搜索树中序顺序等于排名？
- 为什么在弹栈而非压栈时减少k？
- 提前返回会改变树结构吗？

:::details 算法概述

搜索树中序是递增序列，所以不用再排序。沿左边压栈，弹出时才算访问并减少剩余排名，减到零返回值；否则展开它的右子树。栈保存尚未轮到的祖先，计数器只统计已经正式访问的节点。

:::

## TypeScript 实现

本地保留导出及共用类型导入以便测试。提交时移除模块导入和导出，节点定义使用力扣模板；随机节点的类名按模板调整。

```ts
import { TreeNode } from '../shared.js'

export function kthSmallest(root: TreeNode | null, k: number): number {
  const stack: TreeNode[] = []
  let current = root
  while (current !== null || stack.length > 0) {
    while (current !== null) {
      stack.push(current)
      current = current.left
    }
    const node = stack.pop()!
    // 中序访问的排名从第一小逐次增长
    k--
    if (k === 0) return node.val
    current = node.right
  }
  throw new Error('排名超出节点数量')
}
```

## 复杂度与边界

- 访问前 k 个节点并展开必要祖先，时间 **O(h+k)**，最坏 **O(n)**。
- 辅助栈 **O(h)**，最坏 **O(n)**，不创建完整排序数组，输出只有一个数。
- 输入不修改。
- 树高 h 不保证是 log n，原树可能退化。
