# 0543 二叉树的直径

相关基础：[本章基础](/leetcode/08-binary-tree/)。[官方题目](https://leetcode.cn/problems/diameter-of-binary-tree/)。

## 题目

:::info 题面

**难度**：简单

直径是任意两节点之间最长简单路径的边数，路径不要求经过根，也不要求从根开始。单节点直径是 0，与 0104 按节点数计算最大深度的定义不同。本题树节点之间路径唯一，最长路线可以先向上走到某个转折点，再向下走另一侧。

题面配图用节点和左右连线表示树；示例中作为树的数组按层序列出节点，`null` 表示对应的孩子不存在。数组表示的是连接结构，不要求按数值排序。

:::

### 官方示例

> **示例 1**
>
> 输入：root = [1,2,3,4,5]
> 输出：3

> **示例 2**
>
> 输入：root = [1,2]
> 输出：1

### 约束

- 树中节点数目在范围 [1, 10^4] 内
- -100 <= Node.val <= 100

## 前期思路

### 朴素方法与复杂度

手工可以枚举两端节点，再数它们之间的边，节点对多达平方，而且寻找路径还会增加成本。另一个办法是对每个节点分别求左右子树高度，看看穿过它能形成多长路径，但若每次重新扫描子树，高度信息会被反复计算，退化树上可能 O(n²)。

### 优化依据

任何路径都有离根最近的那个节点，称作这条路径的最高转折点。固定转折点后，最长候选只需要左边能延伸多深、右边能延伸多深。对子树而言，这个高度可以在处理完孩子时一次算出，并返回给父节点，避免父节点再重扫。于是一次从下到上的遍历同时产生高度和更新直径。

### 算法推导

height(node) 规定返回以节点为起点向下到最深叶子的节点数，空树高度 0。左右返回 left 与 right 后，经过当前节点连接两侧的路径有 left+right 条边：左右高度各代表从当前节点伸向该侧的边数。

用这个和更新全局 best。但返回给父节点时，只能选左右中较深的一侧再加当前节点，不能把两边总和返回。因为父节点还要接到当前节点上，若同时带两侧，就形成三叉结构，不再是一条路径。

每条合法路径在自己的最高转折点被本轮候选覆盖；每个候选由左右两条简单下行路线组成，也确实合法，所以全局最大恰好等于直径。递归先取得孩子高度再处理根，属于后序信息汇总。

#### 用数组保存递归原本记住的待办

递归很好地表达了“先求孩子，再算父节点”的依赖，但题目允许一万个节点的长链，当前 JavaScript 环境直接递归会触及调用栈上限。主解把相同顺序改为显式后序任务栈，不改变高度与直径的推导。

每个任务保存节点与 ready 标记。ready=false 表示还需展开孩子，此时先压回该节点的 ready=true 任务，再压右孩子和左孩子。等父节点的 ready=true 再被取出，两个孩子已完成，高度已经写入 heights 表，可以直接读取。没有孩子时高度取零。处理完父节点后把它的单侧高度写入表，供更上层使用。

这相当于把函数调用系统自动保存的暂停点与返回值，明确放进数组和 Map。不会因为树深而增加函数调用层数，但辅助表需要线性空间，不能继续把实现说成只有高度大小的递归栈。

### 变式分析与错误反例

- 错误反例：根只有左孩子，左子树内部左右各很深，直径可能完全在左子树，不经过根。因此只在根计算左右高度和会漏解。另一错误是返回 left+right+1 给父节点，把已分叉的路线继续延伸，得到不存在的路径。
- 若边具有不同权重，需要把高度改成最大向下边权和，初始化与负权处理也要重新规定。若求节点数而不是边数，经过根的候选变为 left+right+1，但空树答案约定也必须同步说明。

## 执行过程示例

根 1，左孩子 2 有孩子 4、5，右孩子 3。

| 处理节点 | 左右高度 | 本节点路径边数 | 向父返回高度 |
| --- | --- | --- | --- |
| 4 和 5 | 0 与 0 | 各 0 | 各 1 |
| 2 | 1 与 1 | 2 | 2 |
| 3 | 0 与 0 | 0 | 1 |
| 1 | 2 与 1 | 3 | 3 |

答案路径可以是 4→2→1→3，边数 3。返回高度与 best 恰巧同为 3，并不表示两个定义相同。

显式实现中，节点2第一次出栈只安排“稍后结算2、展开5、展开4”；4与5写下高度1后，2的结算任务才读取它们并写高度2。表中的返回值在代码中变成 Map 中的记录，手推顺序仍然是孩子先、父节点后。

## 解法复述与检查

复述检查：

- 返回高度与完整直径候选有什么区别？
- 为什么左右高度相加得到边数？
- 显式结算任务为什么必须等两个孩子完成？

:::details 算法概述

最长路径可以按最高转折点分类。每个节点只需要左右向下的最大高度，相加就是经过自己的路径边数，更新全局最大；向父返回时只能返回一条较长分支加自己，因为父节点不能接一个分叉结果。孩子先算完，父节点就不必重复扫描。

为支持合法范围的深链，使用展开与结算两种任务保存在数组栈中，孩子高度写入表后父节点才读取，而不直接递归调用。

:::

## TypeScript 实现

本地保留导出及共用类型导入以便测试。提交时移除模块导入和导出，节点定义使用力扣模板；随机节点的类名按模板调整。

```ts
import { TreeNode } from '../shared.js'

export function diameterOfBinaryTree(root: TreeNode | null): number {
  if (root === null) return 0
  let best = 0
  const heights = new Map<TreeNode, number>()
  const stack: Array<[TreeNode, boolean]> = [[root, false]]
  while (stack.length > 0) {
    const [node, ready] = stack.pop()!
    if (!ready) {
      // 当前结算压在孩子任务下面以形成左后右后根的顺序
      stack.push([node, true])
      if (node.right !== null) stack.push([node.right, false])
      if (node.left !== null) stack.push([node.left, false])
      continue
    }
    const left = node.left === null ? 0 : heights.get(node.left)!
    const right = node.right === null ? 0 : heights.get(node.right)!
    // 两条向下分支在当前节点连接成为完整路径
    best = Math.max(best, left + right)
    // 父节点只能连接当前节点的一条较深分支
    heights.set(node, Math.max(left, right) + 1)
  }
  return best
}
```

## 复杂度与边界

- 按 Map 平均常数操作假设，时间 **O(n)**，每个节点展开和结算各一次。
- 高度表 **O(n)**，显式任务栈 **O(h)**，总辅助空间 **O(n)**，没有深递归调用栈。
- 不修改输入，输出一个数字。
- 测试覆盖一万个节点的合法退化链，结果为9999条边。
