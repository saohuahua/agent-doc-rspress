# 0236 二叉树的最近公共祖先

相关基础：[本章基础](/leetcode/08-binary-tree/)。[官方题目](https://leetcode.cn/problems/lowest-common-ancestor-of-a-binary-tree/)。

## 题目

:::info 题面

**难度**：中等

给出普通二叉树中两个不同节点 p 和 q，返回它们最深的共同祖先。一个节点可以是自己的祖先，所以 p 在 q 上方时答案可以是 p。题目保证两节点都存在；这是普通二叉树，不保证搜索树大小关系。参数是节点引用，判断目标应按引用而非只比较数值。

题面配图用节点和左右连线表示树；示例中作为树的数组按层序列出节点，`null` 表示对应的孩子不存在。数组表示的是连接结构，不要求按数值排序。

:::

### 官方示例

> **示例 1**
>
> 输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 1
> 输出：3

> **示例 2**
>
> 输入：root = [3,5,1,6,2,0,8,null,null,7,4], p = 5, q = 4
> 输出：5

> **示例 3**
>
> 输入：root = [1,2], p = 1, q = 2
> 输出：1

### 约束

- 树中节点数目在范围 [2, 10^5] 内。
- -10^9 <= Node.val <= 10^9
- 所有 Node.val 互不相同 。
- p != q
- p 和 q 均存在于给定的二叉树中。

## 前期思路

### 朴素方法与复杂度

手工可以分别写出根到 p 和根到 q 的路径，找到最后一个共同位置。若给每个目标反复从根重新搜索父节点，可能不断重扫树。树节点没有 parent 字段，因此“从目标往上走”虽容易画，却缺少程序可直接使用的入口。需要先建立每个节点到父节点的映射，让向上移动变成一次查表。

### 优化依据

保存 parents 表记录“孩子对象 → 父对象”，根对应 null。再把 p 到根的全部节点放入一个集合，从 q 向上走，遇到的第一个集合成员就是最近公共祖先。不是把两条完整路径逐项相互扫描，而是用集合快速判断一个位置是否也是 p 的祖先。祖先包含自身，所以 p 和 q 本身也参与判断。

另一种递归思路是让子树向上报告目标或汇合点，但题目允许十万个节点的深链，直接函数递归在当前 Node 环境里无法覆盖这个范围。主解选择父表与显式待办栈，把树的向下访问和目标的向上查找拆成两个可见步骤，避免调用栈溢出。

### 算法推导

先把根入栈，parents记录根到null。每次弹出节点，为其非空孩子记录父关系，并把孩子入栈。发现某个目标时，它到根之间的父关系已经全部建立，因为孩子只有在父节点被发现后才会入表。两个目标都进入表后即可停止继续扫描，不必访问与祖先查找无关的剩余子树。

然后从p开始沿parents上行，把p及全部祖先放入集合。再从q开始沿parents上行，直到发现集合中的节点，返回该对象。这个节点同时是q和p的祖先，因此确实共同；而q的上行顺序由深到浅，第一个共同节点一定最深，不可能还错过它下方的共同祖先。

为什么从q方向最深也就是两者共同意义下的最近？共同祖先都位于同一条根到q路径上，彼此有明确的上下次序，不存在两条并列的祖先分支。p的祖先集合保留全部身份，没有漏掉任何合法汇合点。

题目保证p与q存在。实现额外检查遍历结束后两者是否都已发现，若本地传入外部节点则返回null，避免沿未定义父关系继续走。空根也按本地扩展返回null。整个过程只读原树，不把parent字段写入用户节点。

### 变式分析与错误反例

- 错误反例：把祖先集合只记录父节点而排除p自己，会在p是q祖先时漏掉正确答案。若按大小去左或右，那是在使用不存在的搜索树前提。查找比较节点引用，不是用相等值替代同一对象。
- 若节点可能不在树里，保留本实现的发现检查即可明确返回null，但这属于本地扩展。若要处理大量重复查询，可以只预处理一次父关系，再考虑倍增等结构，反复重建全树父表的成本就不再合适。若树会修改，父关系缓存也要同步更新或失效。

## 执行过程示例

根 3，左孩子 5，右孩子 1，5 的孩子为 6、2。求 p=6、q=2。

| 阶段 | 保存的信息或当前位置 | 原因 |
| --- | --- | --- |
| 发现孩子 | 5到3 1到3 6到5 2到5 | 每条边翻译成向上关系 |
| 从6向上 | 集合包含6 5 3 | 保存p的全部祖先与自身 |
| 从2开始 | 2不在集合 | 不是共同祖先 |
| 从2到5 | 5在集合 | 首次命中 返回5 |

若求5和6，集合包含5和3，从6向上第一步到5就命中。若求5和其祖先3，从3开始即命中，说明自身参与判断很重要。

## 解法复述与检查

复述检查：

- 没有parent字段时如何支持向上行走？
- 为什么祖先集合包含目标自己？
- 从另一目标首次命中集合为何就是最近共同祖先？

:::details 算法概述

首先使用显式栈遍历，为每个孩子记录父节点，直到两个目标都找到。然后把第一个目标到根的整条祖先链存进集合，再让第二个目标从自身向上走，首次命中集合就返回。向上顺序由深到浅，所以首次共同位置就是最近祖先。用对象引用判断身份，原树不做修改。

:::

## TypeScript 实现

本地保留导出及共用类型导入以便测试。提交时移除模块导入和导出，节点定义使用力扣模板；随机节点的类名按模板调整。

```ts
import { TreeNode } from '../shared.js'

export function lowestCommonAncestor(root: TreeNode | null, p: TreeNode, q: TreeNode): TreeNode | null {
  if (root === null) return null
  const parents = new Map<TreeNode, TreeNode | null>([[root, null]])
  const stack: TreeNode[] = [root]
  // 显式待办栈建立父关系避免深树递归溢出
  while ((!parents.has(p) || !parents.has(q)) && stack.length > 0) {
    const node = stack.pop()!
    for (const child of [node.left, node.right]) {
      if (child !== null) {
        parents.set(child, node)
        stack.push(child)
      }
    }
  }
  if (!parents.has(p) || !parents.has(q)) return null
  const ancestors = new Set<TreeNode>()
  let current: TreeNode | null = p
  while (current !== null) {
    ancestors.add(current)
    current = parents.get(current)!
  }
  current = q
  // 从目标向上首次命中的共同祖先就是最深者
  while (current !== null && !ancestors.has(current)) current = parents.get(current)!
  return current
}
```

## 复杂度与边界

- 按 Map 与 Set 平均常数操作假设，时间 **O(n)**，最坏扫描全部节点再走两条祖先链。
- 父表 **O(n)**，祖先集合 **O(h)**，显式遍历栈 **O(h)**，总辅助空间 **O(n)**，不使用深递归调用栈。
- 不修改输入，返回原节点引用，无新树输出。
- 测试覆盖十万个节点的合法退化链与两个不同目标。
