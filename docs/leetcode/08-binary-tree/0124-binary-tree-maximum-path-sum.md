# 0124 二叉树中的最大路径和

相关基础：[本章基础](/leetcode/08-binary-tree/)。[官方题目](https://leetcode.cn/problems/binary-tree-maximum-path-sum/)。

## 题目

:::info 题面

**难度**：困难

在非空二叉树里寻找节点值之和最大的非空简单路径。路径可以从任意节点开始到任意节点结束，不必经过根，但不能重复节点，也不能在某处同时分成三条分支。节点可以是负数，答案也可能为负。返回最大和，不要求返回路径。先读 0543，区分“当前完整路径”与“向父返回的单侧延伸”。

题面配图用节点和左右连线表示树；示例中作为树的数组按层序列出节点，`null` 表示对应的孩子不存在。数组表示的是连接结构，不要求按数值排序。

:::

### 官方示例

> **示例 1**
>
> 输入：root = [1,2,3]
> 输出：6

> **示例 2**
>
> 输入：root = [-10,9,20,null,null,15,7]
> 输出：42

### 约束

- 树中节点数目范围是 [1, 3 * 10^4]
- -1000 <= Node.val <= 1000

## 前期思路

### 朴素方法与复杂度

可以枚举两端节点，找到唯一路径并求和，但节点对多达平方，而且许多分支和重复计算。观察一条合法路径，它有一个离根最近的转折点；其余部分分别沿左右子树向下延伸。固定这个点，只需知道两边各自能贡献的最佳下行链，就不必枚举所有端点。

### 优化依据

与直径不同，分支更长不一定更好，因为负节点会拉低总和。孩子应该返回“从孩子开始向下延伸一条链的最大和”。父节点可以选择不接某一侧，所以负贡献按零看待；但路径本身必须至少有一个节点，因此当前候选始终包含 node.val，不能把整个答案初始为零。

### 算法推导

gain(node) 返回包含当前节点、允许向父继续接的最佳单侧路径和。空节点返回 0。先取得左右 gain，再分别和 0 取最大，代表不选负收益分支。

在当前节点形成完整候选 node.val+left+right，用它更新全局 best。这条路径可以从左侧某后代上来经过当前再去右侧。可是给父节点的返回值只能是 node.val+max(left,right)。如果把左右都带上再接父节点，就形成三叉，违反简单路径要求。

每条合法路径都能按最高点分类。对每个最高点，分别选择左右最佳非负贡献，覆盖以它为转折点的最优路径；全树取最大即全局最优。best 初始为负无穷，使全负树也能选出最大的单节点。子调用即使返回负数，其内部更好的完整路径已经更新过 best，不会丢掉。

#### 把信息回传变成显式待办

上述 gain 是子问题含义，不必通过 JavaScript 函数递归实现。题目允许三万个节点的退化链，在当前 Node 环境中，直接递归到一万层就会溢栈。因此主解用数组栈手工保存调用任务，让合法深树也能运行。

每个任务包含节点和 ready 标记。第一次见到节点时，先压入它的 ready=true 结算任务，再压右孩子、左孩子的展开任务。栈后进先出，所以左右孩子都结算完才会再次取到父节点的结算任务。孩子的单侧贡献保存在 gains 表，父节点读取时已经存在。表中存的仍是刚才推导的 gain，不是完整的左右路径和。空孩子直接贡献零。

这样改变的是保存待办与返回值的方式，候选路径和单侧贡献的公式没有变化，也不会因引擎调用栈上限失败。

### 变式分析与错误反例

- 错误反例：单节点 -3，best 初始化 0 会返回不存在的空路径；正确答案是 -3。根 1，孩子 2 与 3，2 下面还有两条分支，若把子树完整双侧结果直接返回再接父，会算出有分叉而非一条路径的结构。
- 若要求路径必须从根开始，只需计算根的最佳单侧向下和，不再全局比较任意转折点。若要求返回具体路径，需要为最佳候选保存转折点及选择的两侧端点或重建信息，单个最大数值无法还原所有节点。

根 -10，左孩子 9，右孩子 20，20 的孩子 15 和 7。

| 当前节点 | 可用左右贡献 | 更新完整候选 | 向父返回 |
| --- | --- | --- | --- |
| 9 | 0 0 | 9 | 9 |
| 15 | 0 0 | 15 | 15 |
| 7 | 0 0 | 7 | 7 |
| 20 | 15 7 | 42 | 35 |
| -10 | 9 35 | 34 | 25 |

答案 42 留在子树内部，不经过根。20 返回的是 35 而非 42，因为父节点只能接一条从 20 向下的链。

实际代码中的“返回”体现为向 gains 表写入。20 的展开任务先安排自己的结算，再安排7和15；15与7分别写表后，20才读取15和7计算42与35。原表的孩子先、父节点后顺序保持不变。

## 解法复述与检查

复述检查：

- 为什么负贡献可以丢弃但全局答案不能从零开始？
- 完整候选为何能接两边、向父贡献却只能接一边？
- ready结算任务如何保证先读到孩子结果？

:::details 算法概述

按路径最高转折点分类。孩子只返回从自己开始的最佳单侧和，负贡献就不接。当前可以用自身加左右非负贡献形成完整路径来更新全局答案，但向父只带较好的一侧。答案从负无穷开始，确保全负树也选择一个实际节点而不是空路径。

实现时用带展开和结算标记的数组栈代替深递归，先处理孩子再从表里读取它们的单侧值，最后记录父节点值。

:::

## TypeScript 实现

本地保留导出及共用类型导入以便测试。提交时移除模块导入和导出，节点定义使用力扣模板；随机节点的类名按模板调整。

```ts
import { TreeNode } from '../shared.js'

export function maxPathSum(root: TreeNode | null): number {
  if (root === null) return -Infinity
  let best = -Infinity
  const gains = new Map<TreeNode, number>()
  const stack: Array<[TreeNode, boolean]> = [[root, false]]
  while (stack.length > 0) {
    const [node, ready] = stack.pop()!
    if (!ready) {
      // 父节点的结算任务留到两个孩子处理完成之后
      stack.push([node, true])
      if (node.right !== null) stack.push([node.right, false])
      if (node.left !== null) stack.push([node.left, false])
      continue
    }
    // 负贡献可以不选但当前节点必须在候选中
    const left = Math.max(0, node.left === null ? 0 : gains.get(node.left)!)
    const right = Math.max(0, node.right === null ? 0 : gains.get(node.right)!)
    best = Math.max(best, node.val + left + right)
    // 表中只保存允许父节点连接的单侧贡献
    gains.set(node, node.val + Math.max(left, right))
  }
  return best
}
```

## 复杂度与边界

- 按 Map 平均常数操作假设，时间 **O(n)**，每个节点展开和结算各一次。
- 显式任务栈 **O(h)**，贡献表 **O(n)**，总辅助空间 **O(n)**，不使用深递归调用栈。
- 不修改输入，无额外输出结构。
- 题面非空保证 best 最终被更新，若本地传 null 返回负无穷，不应视作题目允许的空路径答案。
- 题面累计数值在 JS 安全整数范围内。
- 三万节点退化链由压力测试覆盖。
