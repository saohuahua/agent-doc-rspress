# 0070 爬楼梯 从路线枚举到计数递推

每次允许上升一阶或两阶，要求统计恰好到达目标台阶的路线数量。直接列举路线能够解决小规模输入，但路线数量随台阶数快速增长。本题从完整枚举出发，通过最后一步分类建立计数关系，再利用结果复用消除重复计算。

相关基础：[本章基础](/leetcode/15-dp/)，并通过 [复杂度与数据结构](/leetcode/00-intro/02-complexity-and-structures) 和 [TypeScript 运行时与递归](/leetcode/00-intro/03-ts-runtime-and-recursion) 理解指数增长及递归调用栈。题目来源：[力扣 70 爬楼梯](https://leetcode.cn/problems/climbing-stairs/)。

## 题目

:::info 题面

**难度**：简单

输入是台阶总数 `n`，本题合法范围为 `1 ≤ n ≤ 45`。输出是走到顶端的不同走法数量，不要求输出每条路线，也不是问最少走几步。

走法与顺序有关。三阶可以走 `1 + 1 + 1`、`1 + 2`、`2 + 1`，所以答案是 3。后两种用了相同数量的一阶和两阶，但发生顺序不同，仍然是不同路线。必须刚好到达目标，跨过目标不算。

这里有两个会决定解法的事实：只能向上走；每一步只可能是一阶或两阶。没有额外限制说明某一阶不能站立，也没有要求记录此前如何到达某一阶。

:::

### 官方示例

> **示例 1**
>
> 输入：n = 2
> 输出：2

> **示例 2**
>
> 输入：n = 3
> 输出：3

### 约束

- 1 <= n <= 45

## 前期思路

### 朴素方法与复杂度

朴素方法从地面开始枚举步长序列：每一步分别扩展一阶和两阶两个分支。恰好到达目标时计数，超过目标时终止该分支；返回上一位置后继续枚举尚未处理的分支。

以四阶为例，最终能列出 `1111`、`112`、`121`、`211`、`22`，共 5 条。这种枚举直接对应题目定义。只要每次把两种选择都试到，且只在恰好到达时计数，就不会漏掉合法路线。

不过，每条分支还会产生新的分支。普通递归逐条尝试，调用次数以指数级增长，可以用 `O(2^n)` 作为上界；精确增长比这个上界稍慢。若不保存路线，只做计数，递归栈最深仍有 `n` 层，辅助空间为 `O(n)`。

### 优化依据

考虑剩余三阶时的完成方法数量。无论此前的步长序列是 `11` 还是 `2`，只要现在剩下的台阶数相同，接下来允许的选择完全相同。普通枚举却会分别重新尝试这三阶的所有路线。

重复计算发生在：**不同历史到达相同的剩余任务后，后续路线被再次完整枚举。** 题目仅要求数量，因此已有的三阶计数 3 可以直接复用，无需重新展开对应路线。

结果复用不意味着合并不同的完整路线。不同历史接上同一段后续，仍然构成不同路线；复用的对象是后续路线的数量，而不是完整路线本身。

### 状态定义与转移依据

剩余三阶与从地面走到第三阶具有相同的计数结果，因为各位置均允许一阶或两阶的动作，且没有禁用台阶。把起点整体平移，每条步长序列仍然合法，两种任务一一对应。因此可以统一记录“从地面走到第 `i` 阶，一共有多少种走法”，记作 `ways[i]`。其中 `i` 表示台阶位置，`ways[i]` 表示对应的路线数量，两者含义不同。

构造状态之间的关系，需要找到一种能够覆盖全部路线的分类依据。完整路线包含多次选择，而最后一步只有一阶或两阶两种可能。固定最后一步后，其余部分恰好构成到达较低台阶的完整路线，因此可以由较小状态的数量计算当前状态。

以第五阶为例，按照最后一步划分得到两类。

- 最后走一阶：此前必定在第四阶。第四阶的每一条路线后面接一个 `1`，都对应一条新路线。
- 最后走两阶：此前必定在第三阶。第三阶的每一条路线后面接一个 `2`，也都对应一条新路线。

这两类没有遗漏，因为题目没有第三种步长；也没有重叠，因为一条具体路线的最后一步不可能同时是一阶和两阶。每条前驱路线追加固定一步只生成一条新路线，反过来删去最后一步也能唯一恢复前驱。

因此到第五阶的数量等于到第四阶的数量加上到第三阶的数量。对一般的 `i`，得到 `ways[i] = ways[i - 1] + ways[i - 2]`。该公式成立的依据是两类路线互不重叠且覆盖全部情况。这种保存子问题结果、按依赖计算新结果的做法叫动态规划。

### 算法推导

#### 初始状态

一阶只有 `1`，所以数量是 1。两阶可以是 `11` 或 `2`，所以数量是 2。这两个值可以直接列出，不需要依赖公式。

从三阶开始，每次只依赖前面两个台阶。先算三阶，再算四阶，直到目标台阶，这样需要的答案都已经存在。若反过来从目标向下直接填表，就会读取尚未计算的值。

也可以定义零阶有一种空路线，再统一从更小位置转移，本实现选择一阶和两阶作为起点，直接使用能够列举确认的初始值。输入本身不包含零阶，不把扩展定义当成本题要求。

#### 空间压缩与变量含义

若使用数组保存所有 `ways`，每个下标对应一个台阶的答案。算第六阶时只读取第五阶和第四阶，不会再直接读取第三阶。为了求一个最终数量，只保留最近两个答案就够了。

进入计算第 `step` 阶的循环时，`twoBack` 表示第 `step - 2` 阶的走法数，`oneBack` 表示第 `step - 1` 阶的走法数。两者相加得到当前答案 `current`。然后旧的 `oneBack` 变成下一轮的 `twoBack`，`current` 变成下一轮的 `oneBack`。

先用临时变量算出当前值，再移动两个历史值，可以避免更新一半后丢失仍需使用的旧值。这正是代码中三条赋值的原因。

#### 正确性依据

初始两个答案已经逐条列举确认。假设前两个答案正确，按最后一步划分就能无重复、无遗漏地构造当前所有路线，因此求和得到当前正确数量。每次循环都把这一事实向前推进一阶。处理完 `n` 后，`oneBack` 就是目标答案，循环也随之结束。

### 变式分析与错误反例

- **错误思路：只统计走了多少次两阶，不区分顺序。** 三阶时，这会把 `12` 和 `21` 合并，从而少算。本题统计有顺序的路线，不是无顺序的配方；用最后一步分类可以保留这个区别。
- **条件变化：允许一阶、两阶或三阶。** 重新考虑最后一步，前驱位置多出 `i - 3`，所以应合并三个更小答案。初始一阶为 1，二阶为 2，三阶为 4，不能只改循环上限。若只求数量，可以保存三个历史值。
- **条件变化：要求返回所有路线。** 只保留数量无法恢复每条路线，需要重新组织枚举并保存路径。输出本身随规模指数增长，不可能靠两个变量在线性时间内列出全部答案。这也说明先看清“返回数量还是方案”会直接改变解法。

## 执行过程示例 五阶楼梯

下表覆盖 `n = 5` 的全部循环。初始化时保存一阶的 1 和两阶的 2。

| 当前目标 | 进入时前两阶数量 | 进入时前一阶数量 | 当前数量及原因 | 更新后的两个值 |
| --- | --- | --- | --- | --- |
| 第三阶 | 一阶为 1 | 二阶为 2 | 1 + 2 = 3 按最后一步分成两类 | 2 和 3 |
| 第四阶 | 二阶为 2 | 三阶为 3 | 2 + 3 = 5 两类前驱各追加固定一步 | 3 和 5 |
| 第五阶 | 三阶为 3 | 四阶为 5 | 3 + 5 = 8 同样覆盖全部最后一步 | 5 和 8 |

表中的 2、3、5、8 均表示路线数量；台阶位置由循环变量 `step` 表示。状态压缩后，变量对应的台阶会随循环推进，变量值仍然表示数量。

## 解法复述与检查

理解检查：

- 直接枚举中哪些子问题被重复计算？
- 为什么最后一步分类既不遗漏也不重叠？
- 初始值 1 和 2 分别对应什么？
- 计算第四阶前两个变量各表示哪一阶的路线数量？

:::details 算法概述

直接尝试每一步会反复求解相同台阶规模的问题。定义到第 i 阶的路线数量，按最后一步分类：从前一阶走一阶，或从前两阶走两阶。两类没有交集且覆盖全部路线，所以数量相加。一阶有一种，两阶有两种，从三阶开始顺序计算。每次只需要前两个答案，因此用两个变量保存，算出新值后向前移动，处理到目标阶就返回最新数量。

:::

## TypeScript 实现

本地使用命名导出便于测试，提交力扣时保留函数名和参数，按编辑器模板移除导出声明即可。

```ts
export function climbStairs(n: number): number {
  // 一阶和二阶的走法可以直接列出
  if (n <= 2) return n

  // 两个变量分别保存当前目标前两阶和前一阶的走法数
  let twoBack = 1
  let oneBack = 2

  for (let step = 3; step <= n; step++) {
    // 按最后一步的长度分成互不重叠的两类
    const current = twoBack + oneBack
    // 先保留旧的前一阶再更新当前结果
    twoBack = oneBack
    oneBack = current
  }

  return oneBack
}
```

## 复杂度与边界

- 时间复杂度 **`O(n)`**，每个台阶只做常数次算术和赋值。
- 辅助空间 **`O(1)`**，没有数组也没有递归栈，输出只是一个数。
- 输入为数字且不会被修改。
`n = 1` 和 `n = 2` 直接返回，避免进入不存在的递推阶段。`n = 45` 返回 `1836311903`，在 JavaScript 安全整数范围内，因此本题用 `number` 足够。若扩大台阶范围，不能默认计数仍然精确，应评估 `bigint`，此时大整数运算成本也不再适合无条件视为常数。函数依赖本题输入约束，不负责验证非整数或负数。
