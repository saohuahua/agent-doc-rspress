# 0139 单词拆分

相关基础：[本章基础](/leetcode/15-dp/)。题目来源：[力扣 139](https://leetcode.cn/problems/word-break/)。

## 题目

:::info 题面

**难度**：中等

给定非空字符串 s 和非空单词字典，判断能否把整个字符串分割成若干字典单词，同一单词允许重复使用。返回布尔值，不要求输出切割方案。所有字符是小写英文字母。必须覆盖整串，不能只找到一个字典单词就算成功，也不能重排字符。

:::

### 官方示例

> **示例 1**
>
> 输入: s = "leetcode", wordDict = ["leet", "code"]
> 输出: true

> **示例 2**
>
> 输入: s = "applepenapple", wordDict = ["apple", "pen"]
> 输出: true

> **示例 3**
>
> 输入: s = "catsandog", wordDict = ["cats", "dog", "sand", "and", "cat"]
> 输出: false

### 约束

- 1 <= s.length <= 300
- 1 <= wordDict.length <= 1000
- 1 <= wordDict[i].length <= 20
- s 和 wordDict[i] 仅由小写英文字母组成
- wordDict 中的所有字符串 互不相同

## 前期思路

### 朴素方法与复杂度

从开头尝试每一个切点，如果左边片段在字典中，就继续处理剩余后缀。全部字符均被覆盖时判定成功，任何位置都无合法词就失败。比如 leetcode 可先切 leet，再切 code；但一种切法失败不能说明所有切法失败，还要回到之前尝试其他切点。完整枚举有指数级的切分组合。

### 优化依据

许多不同的前缀切法会到达同一个字符位置，而从该位置继续能否成功只由剩余字符串决定。反过来看，可以保存“前 i 个字符是否能完整切好”，记为 possible[i]。i 表示长度，不是最后字符下标，所以前 i 个字符用 s.slice(0,i) 表示。possible[0]=true 表示空前缀已经处理完，不需要单词。

状态为 true 并不记录某一种必须使用的切法，而是证明至少有一种可行切法。后续只关心能不能接上新单词，不需要知道前缀具体如何切，这使布尔状态足够。字典用 Set 支持成员查询，先修容器可回看 [哈希基础](/leetcode/01-hash/)。

### 算法推导

计算 possible[end] 时枚举最后一个单词的起点 start。如果 possible[start] 为真，并且 s.slice(start,end) 在字典内，那么可切好的前缀后面追加这个词，就能切好前 end 个字符。找到一个成功起点就设 true 并停止本轮，因为存在性问题不要求找完所有方案。

若所有起点都失败，possible[end] 为假。完整性依据是任何成功切分都有最后一个词，那个词的起点必定会被枚举；其前缀本身必须可切。反过来，满足这两个条件的拼接覆盖连续完整前缀，没有跳过或重复字符。end 从1递增，start小于end，前缀状态均已完成。

### 变式分析与错误反例

- 最长词优先不是可靠贪心：s=abcd、字典[abc,ab,cd]，先取abc后剩余后缀无法匹配，但ab+cd成功。若求所有分割方案，布尔值不足以恢复全部路径，需要记录可用切点并枚举，输出可能指数增长。若字典限制每个词只能用一次，前缀长度无法反映已用资源，原状态也不再足够。

## 执行过程示例

s=aaaa，字典为 [aa]。

| 前缀长度 | 关键候选 | 可行性 |
| --- | --- | --- |
| 0 | 空前缀 | true |
| 1 | a不在字典 | false |
| 2 | 从0切出aa且空前缀可行 | true |
| 3 | 从1切aa但前1字符不可行 其他片段不是词 | false |
| 4 | 从2切aa且前2字符可行 | true |

前缀长度为 2 与 3 的两行说明“片段在字典”本身不够，还要证明它前面的整段已经可切。实现中的逻辑与正是在保护这个连接前提。

## 解法复述与检查

- 为什么空前缀设为真？
- 为什么找到一个起点成功就可以停止？
- 最后应该读哪个状态？

:::details 算法概述

保存每个前缀能否被完整拆分。空前缀可行。对新前缀枚举最后一个词的开始位置，只要更短前缀可行且新片段在字典中，就能证明当前前缀可行。按长度递增计算，最后读整个字符串长度对应的状态。

:::

## 复杂度与边界

- 共有 **O(n²)** 个起止位置组合。
- 在 JavaScript 中创建子串以及首次散列的字符成本可能与片段长度有关，保守时间为 **O(n³)** 加字典构建字符成本，不能只因双循环就无条件写 **O(n²)**。
- 持久辅助空间 **O(n+字典总字符量)**，瞬时子串最多 **O(n)**，无递归栈，不修改输入，输出一个布尔值。

## 分层提示

:::details 提示一 观察方向

成功切分的最后一个词从哪里开始 前面一段必须满足什么

:::

:::details 提示二 需要的信息

保存每个前缀是否已经能够完整切分 不需要保存唯一切法

:::

:::details 提示三 组织步骤

空前缀设真 长度递增枚举最后词起点 检查前缀可行且片段属于字典

:::

## TypeScript 实现

本地使用命名导出供测试调用 提交力扣时按题目入口移除导出声明

```ts
export function wordBreak(s: string, wordDict: string[]): boolean {
  const words = new Set(wordDict)
  // 状态下标表示前缀长度而不是末字符位置
  const possible = new Array<boolean>(s.length + 1).fill(false)
  possible[0] = true
  for (let end = 1; end <= s.length; end++) {
    for (let start = 0; start < end; start++) {
      // 可行前缀与一个完整单词共同组成新前缀
      if (possible[start] && words.has(s.slice(start, end))) {
        possible[end] = true
        break
      }
    }
  }
  return possible[s.length]
}
```
