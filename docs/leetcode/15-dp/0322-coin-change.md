# 0322 零钱兑换

相关基础：[本章基础](/leetcode/15-dp/)。题目来源：[力扣 322](https://leetcode.cn/problems/coin-change/)。

## 题目

:::info 题面

**难度**：中等

给定若干正整数硬币面额，每种可用无限枚，要求恰好凑出 amount 所需最少枚数。无法凑出返回 -1，目标为零返回0。输出不是组合数量，也不是一种具体硬币列表。面额没有承诺包含1，所以无解是真实可能，不应把所有金额默认可达。

:::

### 官方示例

> **示例 1**
>
> 输入：coins = [1, 2, 5], amount = 11
> 输出：3

> **示例 2**
>
> 输入：coins = [2], amount = 3
> 输出：-1

> **示例 3**
>
> 输入：coins = [1], amount = 0
> 输出：0

### 约束

- 1 <= coins.length <= 12
- 1 <= coins[i] <= 2^31 - 1
- 0 <= amount <= 10^4

## 前期思路

### 朴素方法与复杂度

尝试选一枚硬币，剩余金额继续尝试，恰好归零得到方案，负数则失败。在所有成功方案里挑枚数最少的。这种枚举可能指数增长，而且选1再选2与选2再选1都会询问同一个剩余金额，因此后续任务反复求解。使用最大面额优先虽然直观，却缺少保证最优的题目条件。

### 状态定义与依赖

定义 best[value] 为恰好凑出 value 的最少硬币数。剩余问题只与金额有关，因为每种硬币无限供应，不存在“此前已经用掉一枚就不能再用”的资源限制。初始 best[0]=0，其他设为 Infinity，明确表示尚未找到可行组合。

这句话同时固定了不可达状态语义：不能用0填满数组，因为那会错误地表示所有正金额都无需硬币。也不能把 -1 直接参与最小值比较，否则不可达反而看起来比任何合法方案更优。先用正无穷参与计算，最终才转换成接口要求的 -1。

### 算法推导

对当前金额 value，枚举最后一枚硬币 coin。若 coin<=value，此前金额应为 value-coin，候选枚数为 best[value-coin]+1。对所有面额取最小。当子问题不可达时，Infinity+1仍为Infinity，不会制造假方案。

只连接最优子问题的依据是：固定最后硬币后，任何更差的剩余方案都会让总枚数更多；把它替换为剩余金额最优方案不会改变总面值。所有合法方案都有最后一枚，枚举覆盖全部，取最小便能找到最优。金额由小到大计算，而所有面额为正，所以每次读取的是更小且已求解金额。

### 变式分析与错误反例

- 若每种硬币只有一枚，剩余金额的最优方案可能已经用过当前硬币，直接连接会非法复用，应使用零一选择的状态或倒序金额更新。若求组合数量，重复顺序是否计为不同方案会影响循环组织，本题取最小可以忽略顺序差异，不能迁移成计数时照抄。无解反例 [2] 凑3，所有候选最终仍是Infinity，必须返回-1而不是0或Infinity。

## 执行过程示例

面额 [1,3,4]，目标6。

| 金额 | 末硬币候选给出的数量 | 结果 |
| --- | --- | --- |
| 0 | 不用硬币 | 0 |
| 1 | 用1接零 | 1 |
| 2 | 用1接一 | 2 |
| 3 | 用1得3枚 用3得1枚 | 1 |
| 4 | 用1得2枚 用3得2枚 用4得1枚 | 1 |
| 5 | 用1得2枚 用3得3枚 用4得2枚 | 2 |
| 6 | 用1得3枚 用3得2枚 用4得3枚 | 2 |

最后得到3+3两枚，而最大面额优先会用4+1+1三枚。表格不是在维护唯一硬币序列，只维护最小数量，因此等价顺序不会影响最小值结果。

## 解法复述与检查

- 为什么未知状态不能填零？
- 不同顺序重复出现为什么不影响这道最小值题？

:::details 算法概述

保存每个金额的最少硬币数。零金额用零枚，其他先视为不可达。从小金额开始枚举最后一枚硬币，把剩余金额答案加一作为候选并取最小。面额为正保证依赖先计算完成；最终仍不可达才返回负一。

:::

## 复杂度与边界

- 若有 k 种面额、目标为 A，时间 **O(kA)**，辅助空间 **O(A)**，没有递归栈，不修改 coins，输出常数空间。
- amount=0不执行外循环，返回0。
- 面额大于当前金额直接跳过。
- 题目内数值精确，Infinity仅用于不可达哨兵，不能误作合法计数。

## 分层提示

:::details 提示一 观察方向

比较面额一三四凑六的方案 最大面额优先是否最优

:::

:::details 提示二 需要的信息

固定最后一枚后 只需要剩余金额的最少数量

:::

:::details 提示三 组织步骤

零初始化为零 其他不可达 金额递增枚举末硬币 取最小并在结尾转换无解状态

:::

## TypeScript 实现

本地使用命名导出供测试调用 提交力扣时按题目入口移除导出声明

```ts
export function coinChange(coins: number[], amount: number): number {
  // 正无穷表示当前还没有合法组合
  const best = new Array<number>(amount + 1).fill(Infinity)
  best[0] = 0
  for (let value = 1; value <= amount; value++) {
    for (const coin of coins) {
      if (coin <= value) best[value] = Math.min(best[value], best[value - coin] + 1)
    }
  }
  // 计算完成后才把不可达状态转换成接口约定
  return best[amount] === Infinity ? -1 : best[amount]
}
```
