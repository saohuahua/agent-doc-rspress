# 0347 前 K 个高频元素

本题按照出现次数选择元素，而不是按照数值大小排序。频次统计将重复输入压缩成不同元素的记录，随后可利用频次的有限范围组织选择过程。

相关基础：[本章基础](/leetcode/13-heap/)。[力扣原题](https://leetcode.cn/problems/top-k-frequent-elements/)。

## 题目

:::info 题面

**难度**：中等

输入非空整数数组和k，返回出现频率最高的k个不同元素，输出顺序不限，题目保证答案唯一。一个值即使出现很多次也只输出一次。进阶要求时间优于 O(n log n)。

:::

### 官方示例

> **示例 1**
>
> 输入：nums = [1,1,1,2,2,3], k = 2
> 输出：[1,2]

> **示例 2**
>
> 输入：nums = [1], k = 1
> 输出：[1]

> **示例 3**
>
> 输入：nums = [1,2,1,2,1,2,3,1,3,2], k = 2
> 输出：[1,2]

### 约束

- 1 <= nums.length <= 10^5
- -10^4 <= nums[i] <= 10^4
- k 的取值范围是 [1, 数组中不相同的元素的个数]
- 题目数据保证答案唯一，换句话说，数组中前 k 个高频元素的集合是唯一的

### 进阶要求

时间复杂度必须优于 O(n log n)。

## 前期思路

### 朴素方法与复杂度

先统计每个值出现几次，再把所有不同值按次数降序排列，取前k个。设不同值有u个，这需要O(n)统计和O(u log u)排序。手工做时可以先画表，例如1出现3次、2出现2次、3出现1次。表中的键是数值，参与排名的是次数，二者不能混淆。

### 优化依据

排序确定了所有候选两两之间的次序，但输出只要最高频的k项。上一题的候选堆可以保留这k项，时间O(n+u log(k+1))，当k很小时很有用。然而k和u都接近n的数量级时，这个上界仍可达到O(n log n)，不能说它无条件完成了进阶。还要寻找题目提供的额外限制：出现次数一定是1到n之间的整数。

### 算法推导

既然频次范围有限，可以让数组下标直接代表频次。创建buckets，其中buckets[f]保存所有恰好出现f次的不同数值。先用Map统计完整频次，再把每个条目按照次数放入对应桶。桶里只放数值，不重复放它出现的每一个位置。

例如1出现3次就把数值1放到3号桶，而不是把3存到1号桶，也不是连续放入三个1。每个不同数值只归属于一个确定频次桶，这一步保留了所有排名需要的信息。接着从n号桶一路向1号桶扫描，将桶内元素加入答案，满k个立即返回。

比较排序可以省略，因为高编号桶的所有值必然比低编号桶的值出现更多次，桶编号已经代表完整的频次等级。从高到低取值，任何未取低频值都不可能优于已取高频值。同频桶内顺序无关；题目保证答案唯一，因此选中与未选中之间不会有造成答案歧义的边界平局。

统计、建桶、扫描空桶各至多线性。虽然有外层频次循环和内层桶循环，但所有桶内元素总共只有u个，不是每个桶都有u项。这是利用有限整数范围，用额外空间换掉通用比较排序。

### 变式分析与错误反例

- 若频率来自另一张含巨大计数的外部表，最大频次不再受本次输入条目数量限制，直接按次数开桶可能非常浪费，此时容量k的候选堆更合适。若要求并列时数值较小者优先，桶内还需处理额外排序规则，不能继续声称原样输出满足新要求。
- 错误反例：`[100,1,1]`取一个最高频值，答案是1不是100。若把输入的每次出现都重复放进桶，取两个结果时可能得到两个1，违反返回不同元素的要求。若把频次作为结果输出，则回答了出现几次而非哪些值。

## 执行过程示例

数组`[1,1,1,2,2,3]`，k为2，n为6。

| 步骤 | 保存的信息 | 理由 |
| --- | --- | --- |
| 计数 | 1到3次 2到2次 3到1次 | 每个值只对应一份频次记录 |
| 建桶 | 3号桶放1 2号桶放2 1号桶放3 | 桶号是出现次数 |
| 扫描6到4号桶 | 都为空 | 没有这么高频的值 |
| 扫描3号桶 | 取出1 | 当前最高非空频次 |
| 扫描2号桶 | 取出2 已满两项 | 更低频不用再取 |

答案为`[1,2]`，不需要输出次数3与2。

## 解法复述与检查

- 数值、频次和桶下标分别表示什么？
- 为什么嵌套循环仍是线性？
- 候选堆为什么不能保证所有合法k下都优于n log n？

:::details 算法概述

首先用Map统计每个不同值的次数。频次只可能在1到n之间，所以用桶下标直接表示频次，把每个不同值放进它的次数桶。从高频桶向低频桶取满k个值，就得到答案。扫描桶至多n次，桶内元素总共至多n个，所以总体线性，不需要比较排序。

:::

## TypeScript 实现

```ts
export function topKFrequent(nums: number[], k: number): number[] {
  const counts = new Map<number, number>()
  for (const num of nums) counts.set(num, (counts.get(num) ?? 0) + 1)
  // 桶下标代表频次 每个不同数值只进入一个桶
  const buckets = Array.from({ length: nums.length + 1 }, () => [] as number[])
  for (const [value, count] of counts) buckets[count].push(value)
  const answer: number[] = []
  for (let frequency = nums.length; frequency >= 1; frequency--) {
    for (const value of buckets[frequency]) {
      answer.push(value)
      if (answer.length === k) return answer
    }
  }
  return answer
}
```

## 复杂度与边界

- 平均Map操作模型下，统计**O(n)**、建桶**O(n+u)**、扫描**O(n+u)**，总时间**O(n)**，满足进阶。
- 辅助空间**O(n+u)**，可简写**O(n)**，输出另占**O(k)**。
- 不修改输入。
- k在1到不同值数量之间，保证可以收集足够结果。
- 频次上界来自数组长度，不受数值正负或大小影响。

## 分层提示

:::details 提示一 先观察什么

先统计次数 再问出现次数的最大可能值是多少

:::

:::details 提示二 需要维护什么信息

频次是有限整数 可以用数组下标表示等级 桶内存具体数值

:::

:::details 提示三 如何组织步骤

Map计数 按频次入桶 从高往低取满k项 所有桶内元素总数只有不同值数量

:::
